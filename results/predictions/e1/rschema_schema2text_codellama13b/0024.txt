The database name is rschema_0024, and it is used to store information about agricultural and sideline products, employees, departments, purchase records, processing records, and sales records. The database has six tables: agricultural_and_sideline_products, employee, department, purchase_record, processing_record, and sales_record.
The agricultural_and_sideline_products table has four columns: product_id, product_name, origin, and primary key (product_id). The employee table has eight columns: employee_id, name, gender, telephone, position, department_id, joining_time, and primary key (employee_id). The department table has six columns: department_id, department_name, person_in_charge_id, department_responsibilities, total_number_of_people_in_the_department, and primary key (department_id). The purchase_record table has ten columns: product_id, purchase_time, purchase_quantity, purchase_person_id, purchase_price, shipper_name, shipping_address, shipping_time, shipper_phone, and primary key (product_id, person_in_charge_id, purchase_time). The processing_record table has six columns: product_id, processing_time, processing_quantity, person_in_charge_id, processing_cost, and primary key (product_id, person_in_charge_id, processing_time). The sales_record table has ten columns: product_id, sales_time, sales_quantity, salesperson_id, sales_price, sales_location, customer_name, customer_phone_number, customer_address, and primary key (product_id, sales_time, salesperson_id).
The foreign key constraints in the purchase_record and processing_record tables reference the employee table, and the foreign key constraints in the sales_record table reference the agricultural_and_sideline_products table. The foreign key constraints in the department table reference the employee table. The update and delete rules for the foreign key constraints are CASCADE and RESTRICT, respectively.
In summary, the rschema_0024 database schema stores information about agricultural and sideline products, employees, departments, purchase records, processing records, and sales records. The schema has six tables, each with its own set of columns and foreign key constraints. The primary keys and foreign key constraints ensure data integrity and referential integrity in the database.
