The database schema, rschema_0120, is used to store information about users, game characters, corporations, user login records, applications, and API keys. The schema consists of six tables: user, game_character, corporation, user_login_record, application, and api_key.
The user table contains information about each user, including their user ID, username, password, email, and active status. The user ID is the primary key and is used to uniquely identify each user.
The game_character table contains information about each game character, including their character ID, character name, corporation, active status, and whether they are the default character. The character ID is the primary key and is used to uniquely identify each character. The corporation column references the corporation table, and the ceo_id column references the user table.
The corporation table contains information about each corporation, including their corporation ID, ticker, corporation name, CEO ID, and active status. The corporation ID is the primary key and is used to uniquely identify each corporation. The CEO ID column references the user table.
The user_login_record table contains information about each user login, including the user ID, source address, browser agent, login result, and timestamp. The user ID is the primary key and is used to uniquely identify each login record. The source address and browser agent columns are not nullable, and the login result column is not nullable and has a default value of "success".
The application table contains information about each application, including the application ID, application name, maintainer, key, callback URL, and active status. The application ID is the primary key and is used to uniquely identify each application. The key column references the api_key table, and the maintainer column references the user table.
The api_key table contains information about each API key, including the key and corporation. The key is the primary key and is used to uniquely identify each API key. The corporation column references the corporation table.
In summary, the schema is used to store information about users, game characters, corporations, user login records, applications, and API keys. Each table has its own set of columns, and some columns reference other tables. The schema is designed to ensure data integrity by using primary keys, foreign keys, and unique constraints.
