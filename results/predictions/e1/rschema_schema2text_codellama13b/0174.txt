The rschema_0174 database is used to store information about patients and their vital signs. It contains three tables: Patient, Vital_signs, and Monitoring.
The Patient table contains information about each patient, including their address, admission time, gender, ID card number, medical record number, name, and phone number. The medical record number is the primary key for this table.
The Vital_signs table contains information about the different vital signs that can be monitored, including their names and the normal range of values for each sign. The feature name is the primary key for this table.
The Monitoring table contains information about the actual values of each vital sign for each patient. It includes the feature name, feature value, medical record number, record time, and the foreign keys to the Vital_signs and Patient tables. The primary key for this table is a composite of the medical record number, feature name, and record time.
The foreign keys in the Monitoring table reference the feature name in the Vital_signs table and the medical record number in the Patient table. The update and delete rules for these foreign keys are CASCADE and RESTRICT, respectively.
In summary, the rschema_0174 database is used to store information about patients and their vital signs, with three tables that are related through foreign keys. The Patient table contains information about each patient, the Vital_signs table contains information about the different vital signs, and the Monitoring table contains information about the actual values of each vital sign for each patient.
