The database schema "rschema_0420" is used to store information about a video learning platform. It contains 12 tables, each representing a different entity or relationship in the system. The tables are:
1. User: This table stores information about the users of the platform, including their username, password, phone number, WeChat open ID, name, QQ number, email, registration time, and account status. The primary key is the user ID.
2. News: This table stores information about the news articles on the platform, including the news ID, title, content, publication time, read count, news status, and category ID. The primary key is the news ID.
3. Video Category Assignment: This table stores information about the assignment of videos to categories. Each row represents a video and its corresponding category. The primary key is the video ID and category ID.
4. News Category Assignment: This table stores information about the assignment of news articles to categories. Each row represents a news article and its corresponding category. The primary key is the news ID and category ID.
5. News Category: This table stores information about the categories of news articles. Each row represents a category and its corresponding name, sort order, and parent category ID (if applicable). The primary key is the category ID.
6. Video: This table stores information about the videos on the platform, including the video ID, title, description, cover image URL, market, directory structure, course count, total duration, price, video status, and category ID. The primary key is the video ID.
7. Instructor: This table stores information about the instructors on the platform, including their instructor ID, name, avatar, title, introduction, teaching experience, professional field, teaching achievements, and instructor courses. The primary key is the instructor ID.
8. Video Category: This table stores information about the categories of videos. Each row represents a category and its corresponding name, parent category ID (if applicable), and child category ID (if applicable). The primary key is the category ID.
9. Instructor Course: This table stores information about the courses taught by instructors. Each row represents an instructor and their corresponding video ID and instructor ID. The primary key is the video ID and instructor ID.
10. User Collection: This table stores information about the videos that users have collected. Each row represents a user and their corresponding video ID, collection time, and valid status. The primary key is the video ID and user ID.
11. User Video Order: This table stores information about the orders placed by users for videos. Each row represents a user and their corresponding video ID, order time, payment amount, payment method, payment status, payment time, and order status. The primary key is the video ID, user ID, and order time.
12. User Learning Record: This table stores information about the learning records of users for videos. Each row represents a user and their corresponding video ID, purchase time, expiration time, viewing duration, last viewing time, and completion status. The primary key is the video ID, user ID, and purchase time.
The schema also includes foreign key constraints to enforce referential integrity, ensuring that the data in each table is consistent and accurate. For example, the foreign key constraints in the Video Category Assignment and News Category Assignment tables ensure that the category IDs referenced in those tables exist in the corresponding category tables. Similarly, the foreign key constraints in the Instructor Course and User Learning Record tables ensure that the instructor IDs and video IDs referenced in those tables exist in the corresponding instructor and video tables.
