The database named "rschema_0443" contains seven tables that are used to store information about users, assets, status logs, account dynamic logs, user-asset relationships, device-log relationships, and asset-account dynamic log relationships. The tables are designed to enforce entity integrity, referential integrity, and data consistency.
The "user_information" table contains information about users, including their user ID, username, login password, registered phone number, role permissions, and a primary key on the user ID column.
The "asset_information" table contains information about assets, including their device ID, device name, device number, device model, device status, calibration date, calibration validity, calibration result, device location, department, responsible person, and remarks. The table also has a primary key on the device ID column.
The "status_log_information" table contains information about status logs, including the log ID, device number, borrow receiver, borrow time, borrow device photo, IOU photo, receiver, receiving area, receiving time, receiving device photo, return person, return time, return device photo, data monitoring, and remarks. The table has a primary key on the log ID column and a foreign key on the device number column that references the device ID column in the "asset_information" table.
The "account_dynamic_log_information" table contains information about account dynamic logs, including the dynamic log ID, device number, borrow operation account, receive operation account, return operation account, and remarks. The table has a primary key on the dynamic log ID column and a foreign key on the device number column that references the device ID column in the "asset_information" table.
The "user_asset_relationship" table contains information about user-asset relationships, including the user ID and device number. The table has a primary key on the user ID and device number columns and foreign keys on the user ID column that references the user ID column in the "user_information" table and the device number column that references the device ID column in the "asset_information" table.
The "device_number,_log_id" table contains information about device-log relationships, including the device number and log ID. The table has a primary key on the log ID and device number columns and foreign keys on the log ID column that references the log ID column in the "status_log_information" table and the device number column that references the device ID column in the "asset_information" table.
The "asset_account_dynamic_log_relationship" table contains information about asset-account dynamic log relationships, including the device number and dynamic log ID. The table has a primary key on the dynamic log ID and device number columns and foreign keys on the dynamic log ID column that references the dynamic log ID column in the "account_dynamic_log_information" table and the device number column that references the device ID column in the "asset_information" table.
Overall, the schema is designed to store and manage information about users, assets, status logs, account dynamic logs, user-asset relationships, device-log relationships, and asset-account dynamic log relationships in a consistent and organized manner.
