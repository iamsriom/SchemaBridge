The database schema for the database named 'rschema' consists of 5 tables. The tables are 'document', 'document_management_personnel', 'approval_record', 'archiving_record', and 'query_record'.
The 'document' table represents the documents that need to be managed. It has columns for 'document_id', 'name', 'category', 'creation_time', and 'status'. All these columns allow null values.
The 'document_management_personnel' table represents the personnel involved in the document management process. It has columns for 'employee_id', 'name', 'gender', 'position', and 'contact_information'. Again, all these columns allow null values.
The 'approval_record' table represents the approval records of the documents. It has columns for 'document_id', 'approver', 'approval_time', and 'approval_comments'. The primary key is a composite key consisting of 'approval_time', 'approver', and 'document_id'. The 'approver' column references the 'employee_id' in the 'document_management_personnel' table, and the 'document_id' references the 'document_id' in the 'document' table. If a document or a personnel record is deleted, the corresponding approval records will be deleted as well due to the cascading delete constraints.
The 'archiving_record' table represents the archiving records of the documents. It has columns for 'document_id', 'archivist', 'archiving_time', and 'archiving_location'. The primary key is a composite key consisting of 'archivist' and 'document_id'. The 'archivist' column references the 'employee_id' in the 'document_management_personnel' table, and the 'document_id' references the 'document_id' in the 'document' table. If a document or a personnel record is deleted, the corresponding archiving records will be deleted as well due to the cascading delete constraints.
Finally, the 'query_record' table represents the query records of the documents. It has columns for 'document_id', 'query_personnel', 'query_time', and 'query_result'. The primary key is a composite key consisting of 'query_personnel', 'query_time', and 'document_id'. The 'query_personnel' column references the 'employee_id' in the 'document_management_personnel' table, and the 'document_id' references the 'document_id' in the 'document' table. If a document or a personnel record is deleted, the corresponding query records will be deleted as well due to the cascading delete constraints.
