The database schema for the database named 'rschema' consists of 6 tables.
The 'agricultural_and_sideline_products' table represents the products produced in the agricultural and sideline industries. It has a primary key 'product_id' and includes 'product_name' and 'origin' as columns.
The 'employee' table is used to store information about the employees. It has a primary key 'employee_id', and includes 'name', 'gender', 'telephone', 'position', 'department_id', and 'joining_time' as columns.
The 'department' table is used to store information about the departments within the company. It has a primary key 'department_id', and includes 'department_name', 'person_in_charge_id', 'department_responsibilities', and 'total_number_of_people_in_the_department' as columns. It has a foreign key 'person_in_charge_id' that references the 'employee_id' in the 'employee' table.
The 'purchase_record' table is used to store information about the purchase records. It has a primary key composed of 'person_in_charge_id', 'product_id', and 'purchase_time'. It has foreign keys 'person_in_charge_id' and 'product_id' that reference the 'employee_id' and 'product_id' in the 'employee' and 'agricultural_and_sideline_products' tables respectively.
The 'processing_record' table is used to store information about the processing records. It has a primary key composed of 'person_in_charge_id', 'product_id', and 'processing_time'. It has foreign keys 'person_in_charge_id' and 'product_id' that reference the 'employee_id' and 'product_id' in the 'employee' and 'agricultural_and_sideline_products' tables respectively.
Finally, the 'sales_record' table is used to store information about the sales records. It has a primary key composed of 'sales_time', 'product_id', and 'salesperson_id'. It has foreign keys 'product_id' and 'salesperson_id' that reference the 'product_id' and 'employee_id' in the 'agricultural_and_sideline_products' and 'employee' tables respectively. The database schema is designed to maintain referential integrity, with cascading delete and update operations set up to maintain data consistency across the tables.
