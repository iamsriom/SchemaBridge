The database schema for the database named 'rschema' consists of 5 tables: 'timber', 'department', 'employee', 'timber_procurement', and 'timber_processing'.
The 'timber' table represents the timber resources in the company. It has columns for 'timber_id', 'timber_name', 'timber_type', 'procurement_price', 'processing_cost', and 'sales_price'. All these columns allow null values and are of type varchar(255).
The 'department' table represents the departments within the company. It has columns for 'department_id', 'department_name', 'supervisor', and 'contact_information'. All these columns allow null values and are of type varchar(255). The 'supervisor' column is a foreign key referencing the 'employee' table's 'employee_id' column.
The 'employee' table represents the employees within the company. It has columns for 'employee_id', 'name', 'gender', 'phone_number', 'position', and 'department'. All these columns allow null values and are of type varchar(255). The 'department' column is a foreign key referencing the 'department' table's 'department_id' column.
The 'timber_procurement' table represents the procurement of timber resources. It has columns for 'timber_id', 'employee_id', 'procurement_quantity', 'supplier', and 'procurement_time'. All these columns allow null values and are of type varchar(255). The 'timber_id' and 'employee_id' columns are foreign keys referencing the 'timber' and 'employee' tables' 'timber_id' and 'employee_id' columns respectively.
The 'timber_processing' table represents the processing of timber resources. It has columns for 'timber_id', 'employee_id', 'processing_quantity', and 'processing_time'. All these columns allow null values and are of type varchar(255). The 'timber_id' and 'employee_id' columns are foreign keys referencing the 'timber' and 'employee' tables' 'timber_id' and 'employee_id' columns respectively.
The primary keys of all these tables are their respective 'id' columns. The foreign key constraints ensure referential integrity by maintaining the relationship between the tables. On delete and update operations, the cascade option is set to ensure that if a record in the parent table is deleted or updated, the corresponding records in the child table will automatically be deleted or updated.
