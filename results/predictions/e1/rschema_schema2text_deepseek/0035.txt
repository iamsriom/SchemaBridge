The database schema named 'rschema_0035' consists of three tables: 'Customer', 'Project', and 'Customer_Project_Relationship'.
The 'Customer' table represents a customer entity and contains five columns: 'Address', 'Customer_ID', 'Email', 'Name', and 'Phone'. The 'Customer_ID' column is the primary key of this table.
The 'Project' table represents a project entity and contains six columns: 'Actual_Completion_Date', 'Estimated_Completion_Date', 'Project_Budget', 'Project_ID', 'Project_Name', and 'Start_Date'. The 'Project_ID' column is the primary key of this table.
The 'Customer_Project_Relationship' table represents the relationship between customers and projects. It contains five columns: 'Customer_ID', 'Feedback', 'Project_ID', 'Satisfaction_Rating', and both 'Customer_ID' and 'Project_ID' are primary keys. 'Customer_ID' is a foreign key referencing the 'Customer' table, and 'Project_ID' is a foreign key referencing the 'Project' table. The combination of 'Customer_ID' and 'Project_ID' ensures entity integrity as it prevents the same customer from being associated with the same project more than once.
The 'Customer' table allows null values in the 'Address', 'Email', and 'Phone' columns, while the 'Project' table allows null values in the 'Project_Name' column. If a null value is inserted into these columns, it signifies that the corresponding information is not available.
The 'Customer_Project_Relationship' table has update and delete rules set to CASCADE, which means if a record in the 'Customer' or 'Project' table is updated or deleted, the corresponding records in the 'Customer_Project_Relationship' table will be updated or deleted as well. This ensures referential integrity.
The schema is exhaustive, covering all the necessary entities and their relationships, and provides a comprehensive framework for managing customer and project data.
