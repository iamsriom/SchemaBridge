The database schema named 'rschema_0036' consists of four tables: Project, Contract, Project_Includes_Contract, and Contract_Change_Record.
The Project table represents the project details. It includes columns for Actual_Completion_Date (a datetime), Budget (a float), Expected_Completion_Date (a datetime), Location (a varchar of 255 characters), Project_Name (a varchar of 255 characters), Project_Number (an integer, primary key), and Start_Date (a datetime).
The Contract table represents the contract details. It includes columns for Contract_Amount (a float), Contract_Name (a varchar of 255 characters), Contract_Number (an integer, primary key), Contract_Status (a varchar of 255 characters), Project_Number (an integer, not null, foreign key referencing the Project table), and Signing_Date (a datetime).
The Project_Includes_Contract table represents the relationship between projects and contracts. It includes columns for Contract_Number (an integer, not null, foreign key referencing the Contract table) and Project_Number (an integer, not null, foreign key referencing the Project table), both of which together form the primary key.
The Contract_Change_Record table represents the change records for contracts. It includes columns for Change_Amount (an integer), Change_Content (a varchar of 255 characters), Change_Date (a datetime), Change_Number (an integer, primary key), Contract_Number (an integer, not null, foreign key referencing the Contract table).
All columns allow null values except for the ones that are not null. There are no default values. The primary keys are the Contract_Number in the Contract table and the combination of Project_Number and Contract_Number in the Project_Includes_Contract table. The foreign keys enforce referential integrity by ensuring that the values in the foreign key columns of child tables match the values in the primary key columns of the parent tables. The foreign key constraints are set to CASCADE on delete and update.
