The database schema named 'rschema_0061' consists of three tables: 'patent', 'inventor', and 'patent_application_record'.
The 'patent' table is used to store information about patents. It has five columns: 'patent_number', 'patent_name', 'application_date', 'status', and 'patent_number' as the primary key. The 'patent_number' column is a varchar data type and does not allow null values.
The 'inventor' table stores information about inventors. It has seven columns: 'inventor_number', 'name', 'date_of_birth', 'gender', 'phone', 'position', and 'inventor_number' as the primary key. All columns are varchar data types and do not allow null values.
The 'patent_application_record' table is used to record the patent application records. It has three columns: 'patent_number', 'inventor_number', and 'application_date', and these three columns form the primary key of this table. 'patent_number' and 'inventor_number' are foreign keys referencing the 'patent' and 'inventor' tables respectively. The foreign key constraints are set to ON DELETE CASCADE and ON UPDATE CASCADE, which means that if a patent or inventor record is deleted or updated, the corresponding records in the 'patent_application_record' table will also be deleted or updated.
This schema ensures the integrity of the data by enforcing referential integrity through foreign key constraints. It also ensures entity integrity by having a primary key for each table. The schema is designed to be exhaustive and readable for a non-expert.
