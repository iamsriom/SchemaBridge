The database schema named 'rschema_0066' consists of four tables: 'community', 'owner', 'house', and 'repair_application_record'.
The 'community' table represents a community, with columns for 'community_id', 'community_name', 'address', and 'manager'. It has 'community_id' as the primary key.
The 'owner' table represents the owners of the houses in the community. It has columns for 'owner_id', 'name', 'phone', 'house_number', and 'community_id'. The 'owner_id' is the primary key and 'community_id' is a foreign key referencing the 'community' table.
The 'house' table represents the houses in the community. It has columns for 'house_id', 'house_name', and 'location'. 'house_id' is the primary key.
The 'repair_application_record' table represents the repair application records. It has columns for 'owner_id', 'house_id', 'application_time', 'repair_content', and 'repair_cost'. Both 'owner_id' and 'house_id' are foreign keys referencing the 'owner' and 'house' tables respectively. The combination of 'owner_id' and 'house_id' forms the primary key.
The database schema is set up to maintain referential integrity by using foreign key constraints. When a record in the 'owner' table is deleted or updated, the corresponding records in the 'repair_application_record' table will be deleted or updated as well due to the cascade delete and update rules.
