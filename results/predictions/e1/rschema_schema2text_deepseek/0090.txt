The database schema named 'rschema_0090' consists of eight tables. The primary function of this schema is to manage and organize various aspects of a conference, including user authentication, venue selection, conference creation, session scheduling, and user participation in conferences.
The 'User' table represents the conference attendees. It contains columns for authentication method, email, name, user ID (which is the primary key), and user permission. Each user can have different authentication methods and permissions, and their details are stored in this table.
The 'Venue' table holds information about the venues where conferences can be held. It includes geographic location, venue address, venue ID (which is the primary key), and venue name.
The 'Conference' table is used to create and manage conferences. It includes columns for the ID of the conference, the time of the conference, the ID of the conference's administrator and creator, subtitle, and title. The administrator and creator are foreign keys referencing the User table.
The 'Session' table is used to schedule and manage sessions within conferences. It includes columns for the abstract, ID of the conference the session belongs to, duration, session ID (which is the primary key), ID of the speaker, start time, and title. The conference ID is a foreign key referencing the Conference table.
The 'Conference_Venue_Selection' table is a junction table that links the 'Conference' and 'Venue' tables. It contains columns for the conference ID and venue ID, which are both foreign keys referencing the respective tables.
The 'User_Create_Conference' and 'User_Manage_Conference' tables are also junction tables that link the 'User' and 'Conference' tables. They contain columns for the user ID and conference ID, which are both foreign keys referencing the respective tables.
Finally, the 'User_Presentation' table is a junction table that links the 'User' and 'Session' tables. It contains columns for the session ID and user ID, which are both foreign keys referencing the respective tables. This schema ensures referential integrity by linking all the tables together in a logical and meaningful way.
