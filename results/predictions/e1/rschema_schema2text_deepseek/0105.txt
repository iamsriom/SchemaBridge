The database schema named "rschema_0105" contains four tables: User, User_dynamic_information, Add_Contact, and Social_Activity.
The User table represents the main user information, including Account, Birthday, Email, Gender, Nickname, Password, Phone, Registration_time, and User_ID. It has an integer primary key, User_ID, which is used to uniquely identify each user.
The User_dynamic_information table contains dynamic user information, including Dynamic_ID, Dynamic_content, Number_of_comments, Number_of_favorites, Number_of_likes, Publisher_ID, and Publishing_time. It has an integer primary key, Dynamic_ID, and a foreign key, Publisher_ID, referencing the User table's User_ID.
The Add_Contact table stores information about user contacts, including Add_Time, Added_User_ID, Relationship_Type, Remarks, and User_ID. It has a composite primary key consisting of User_ID, Added_User_ID, and Adding_time. It also has two foreign keys, Added_User_ID referencing User_ID in the User table.
Finally, the Social_Activity table records user activities, including Collection, Comment, Creation_Time, Dynamic_ID, Like, and User_ID. It has a composite primary key consisting of User_ID, User_Dynamic_ID, and Creation_Time. It also has two foreign keys, Dynamic_ID referencing the Dynamic_ID in the User_dynamic_information table, and User_ID referencing User_ID in the User table.
All columns allow null values except for the Publisher_ID column in the User_dynamic_information table and the Dynamic_ID column in the Social_Activity table, which are not null. The default value for the Add_Time column in the Add_Contact table is the current time. The Social_Activity table has a CASCADE delete rule on the Dynamic_ID and User_ID foreign keys, meaning that if a record in the User_dynamic_information table is deleted, all related records in the Social_Activity table will be deleted as well.
