The database schema named 'rschema_0113' consists of four tables: 'product', 'customer', 'order', and 'order_detail'.
The 'product' table represents a product catalogue, with each product having a unique identifier, name, price, inventory quantity, and supplier. The primary key for this table is 'product_id'.
The 'customer' table holds information about the customers, with each customer having a unique identifier, name, address, and contact information. The primary key for this table is 'customer_id'.
The 'order' table records all the orders made by the customers. Each order has a unique identifier, the identifier of the customer ordering, the transaction status, the date of the order, and the update time. The 'ordering_customer' column is a foreign key referencing the 'customer_id' in the 'customer' table. The primary key for this table is 'order_id'.
The 'order_detail' table holds the details of each order. Each record represents a product purchased in an order. It has the 'order_id' and 'product_id' as foreign keys referencing the 'order_id' and 'product_id' in the 'order' and 'product' tables, respectively. The primary key for this table is a composite of 'product_id' and 'order_id'.
The DELETE and UPDATE rules for these foreign keys are set to CASCADE, meaning that if a record in the 'customer', 'order', or 'product' tables is deleted or updated, the corresponding records in the 'order' and 'order_detail' tables will also be deleted or updated. This ensures referential integrity and data consistency.
