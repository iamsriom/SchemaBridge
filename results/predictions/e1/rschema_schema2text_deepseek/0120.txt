The database schema for the database named 'rschema_0120' consists of 6 tables.
The 'user' table is the main entity in the schema, with 'user_id' as the primary key. It contains 'username', 'password', 'email', and 'active_status' columns. The 'user_id' column is set to NOT NULL to ensure that each user has a unique identifier.
The 'game_character' table represents the characters that users can create within the game. It has 'character_id' as the primary key, and 'character_name', 'corporation', 'active_status', and 'is_default_character' columns. The 'corporation' column is a foreign key referencing the 'corporation_id' in the 'corporation' table. The foreign key constraints on this table are set to CASCADE, meaning that if the referenced 'corporation_id' in the 'corporation' table is deleted or updated, the corresponding entries in the 'game_character' table will also be deleted or updated.
The 'corporation' table holds information about the corporations that exist within the game. It has 'corporation_id' as the primary key, and 'ticker', 'corporation_name', and 'ceo_id' columns. The 'ceo_id' column is a foreign key referencing the 'user_id' in the 'user' table.
The 'user_login_record' table keeps track of user login activities. It has 'user_id', 'source_address', 'browser_agent', 'login_result', and 'timestamp' as columns, with 'user_id' and 'source_address' and 'timestamp' forming a composite primary key. The 'user_id' column is a foreign key referencing the 'user_id' in the 'user' table.
The 'application' table represents the applications that users can create. It has 'application_id' as the primary key, and 'application_name', 'maintainer', 'key', 'callback_url', and 'active_status' columns. The 'key' and 'maintainer' columns are foreign keys referencing the 'key' and 'user_id' in the 'api_key' and 'user' tables respectively.
The 'api_key' table holds the API keys that are used by applications. It has 'key' as the primary key, and 'corporation' as a foreign key referencing the 'corporation_id' in the 'corporation' table.
All these tables are set to InnoDB engine and use utf8mb3 character set to ensure data integrity and compatibility with various languages and characters.
