The database schema for the database named 'rschema_0121' consists of 8 tables. The database is designed to manage various aspects of a system, including user authentication, service monitoring, worker node management, and data encryption.
The 'user' table is the main entity in the schema, holding information about each user, including their unique user_id, username, full name, email, password hash, registration date, and last login date. The primary key for this table is the user_id.
The 'authenticated_user' table is a supporting table, storing information about authenticated users, including the user_id, authentication level, signature, issuer, and authentication time. The primary key for this table is the user_id, and there is a foreign key constraint referencing the user table.
The 'service' table holds information about various services, including the service_id, service name, service type, service url, configuration data, last heartbeat time, monitoring status, signature, and issuer. The primary key for this table is the service_id.
The 'worker_node' table contains information about worker nodes, including the node_id, node name, status, service_id, operating system, architecture, last heartbeat time, signature, and issuer. The primary key for this table is the node_id, and there is a foreign key constraint referencing the service table.
The 'authenticated_consumer' table stores information about authenticated consumers, including the consumer_id, user_id, name, description, type, configuration data, permissions, signature, and issuer. The primary key for this table is the user_id and consumer_id, and there is a foreign key constraint referencing the user table.
The 'user_migration' table keeps track of user migrations, including the migration_id, old_user_id, new_user_id, and migration_time. The primary key for this table is the migration_id, and there are foreign key constraints referencing the user table.
Finally, the 'session' table holds information about user sessions, including the session_id, consumer_id, expiration time, mfa_status, signature, and issuer. The primary key for this table is the session_id, and there is a foreign key constraint referencing the authenticated_consumer table.
The 'encrypted_data_test' table stores encrypted data, including the data_id, regular data, sensitive data 1, sensitive data 2, signature, and issuer. The primary key for this table is the data_id.
All these tables are created using InnoDB storage engine and utf8mb3 character set, ensuring data integrity and performance. The schema also includes cascading delete and update operations to maintain data consistency across tables.
