The database schema named 'rschema_0122' comprises six tables: 'conversation', 'message', 'inquiry', 'organization', 'security_base_record', and 'customer'.
The 'conversation' table is used to store information about customer conversations. It has five columns: 'conversation_id', 'customer_id', 'creation_time', 'last_update_time', and 'baseid'. The 'conversation_id' is the primary key and is used to uniquely identify each conversation. The 'baseid' is a foreign key referencing the 'security_base_record' table, which is set to cascade delete and update.
The 'message' table is used to store messages exchanged in the conversations. It has five columns: 'message_id', 'conversation_id', 'content', 'send_time', and 'status'. The 'message_id' is the primary key and is used to uniquely identify each message. The 'conversation_id' is a foreign key referencing the 'conversation' table, which is set to cascade delete and update.
The 'inquiry' table is used to store customer inquiries. It has seven columns: 'customer_id', 'inquiry_category', 'inquiry_content', 'status', 'creation_time', 'end_time', and 'customer_id' and 'creation_time' form the primary key. The 'customer_id' is a foreign key referencing the 'customer' table, which is set to cascade delete and update.
The 'organization' table is used to store information about organizations. It has nine columns: 'organization_id', 'organization_name', 'phone_number', 'avatar', 'location', 'email', 'description', 'homepage_link', and 'image_link'. The 'organization_id' is the primary key and is used to uniquely identify each organization.
The 'security_base_record' table is used to store security-related information. It has three columns: 'baseid', 'encrypted_information', and 'record_creation_time' and 'record_update_time'. The 'baseid' is the primary key and is used to uniquely identify each record.
The 'customer' table is used to store information about customers. It has four columns: 'customer_id', 'name', 'contact_information', and 'belonging_organization'. The 'customer_id' is the primary key and is used to uniquely identify each customer. The 'belonging_organization' is a foreign key referencing the 'organization' table, which is set to cascade delete and update.
