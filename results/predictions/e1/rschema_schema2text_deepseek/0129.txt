The database schema for the database named rschema_0129 consists of four tables: room, user, message, and user_join_room.
The room table is used to store information about the rooms in the system. It has five columns: room_id, room_name, room_description, create_time, and creator. The room_id is the primary key and is used to uniquely identify each room. The creator column is a foreign key referencing the user_id in the user table, with on delete cascade and on update cascade rules to ensure data integrity.
The user table stores information about the users of the system. It has six columns: user_id, username, password, email, phone_number, and registration_time. The user_id is the primary key and is used to uniquely identify each user.
The message table stores information about the messages in the system. It has eight columns: room_id, user_id, message_content, message_type, update_record, create_time, update_time, and is_deleted. The combination of user_id and room_id and create_time forms the primary key. The room_id and user_id are foreign keys referencing the room_id and user_id in the room and user tables respectively, with on delete cascade and on update cascade rules to ensure data integrity.
Finally, the user_join_room table stores information about which users have joined which rooms. It has four columns: user_id, room_id, join_time, and exit_time. The combination of user_id, join_time, room_id, and exit_time forms the primary key. The room_id and user_id are foreign keys referencing the room_id and user_id in the room and user tables respectively, with on delete cascade and on update cascade rules to ensure data integrity.
This schema ensures that all data is properly related and maintains referential integrity, ensuring that all foreign keys point to valid primary keys and that deleting or updating a primary key will also delete or update the corresponding foreign key records.
