The database schema named rschema_0139 consists of 8 tables. The tables are described as follows:
1. **Department**: This table represents the departments in a medical facility. It has two columns: Department_Name, which is a VARCHAR type and represents the name of the department, and Floor, which is also a VARCHAR type and represents the floor on which the department is located. The Department_Name column is the primary key of this table.
2. **Doctor**: This table represents the doctors in the medical facility. It has four columns: Doctor_ID, which is an INTEGER type and represents the unique identifier of the doctor, Gender, which is a VARCHAR type and represents the gender of the doctor, Name, which is a VARCHAR type and represents the name of the doctor, and Title, which is a VARCHAR type and represents the title of the doctor. Doctor_ID is the primary key of this table.
3. **Patient**: This table represents the patients in the medical facility. It has three columns: Age, which is an INTEGER type and represents the age of the patient, Gender, which is a VARCHAR type and represents the gender of the patient, and Patient_Name, which is a VARCHAR type and represents the name of the patient. Patient_Name is the primary key of this table.
4. **Medicine**: This table represents the medicines in the medical facility. It has three columns: Manufacturer, which is a VARCHAR type and represents the manufacturer of the medicine, Medicine_Name, which is a VARCHAR type and represents the name of the medicine, and Price, which is a FLOAT type and represents the price of the medicine. Medicine_Name is the primary key of this table.
5. **Prescription**: This table represents the prescriptions in the medical facility. It has one column: Prescription_Information, which is a VARCHAR type and represents the information about the prescription. Prescription_Information is the primary key of this table.
6. **Diagnosis_Management**: This table represents the management of diagnoses in the medical facility. It has three columns: Diagnosis_Information, which is a VARCHAR type and represents the information about the diagnosis, Doctor_ID, which is an INTEGER type and represents the identifier of the doctor who made the diagnosis, and Patient_Name, which is a VARCHAR type and represents the name of the patient. The combination of Doctor_ID and Patient_Name is the primary key of this table. Doctor_ID and Patient_Name are foreign keys referencing Doctor and Patient respectively.
7. **Prescription_Management**: This table represents the management of prescriptions in the medical facility. It has four columns: Doctor_ID, which is an INTEGER type and represents the identifier of the doctor who made the prescription, Patient_Name, which is a VARCHAR type and represents the name of the patient, Prescription_Information, which is a VARCHAR type and represents the information about the prescription, and Doctor_ID and Patient_Name are foreign keys referencing Doctor and Patient respectively. The combination of Doctor_ID and Patient_Name is the primary key of this table.
8. **Medicine_List_Management**: This table represents the management of medicine lists in the medical facility. It has four columns: Medicine_Name, which is a VARCHAR type and represents the name of the medicine, Prescription_Information, which is a VARCHAR type and represents the information about the prescription, Quantity, which is an INTEGER type and represents the quantity of the medicine, and Medicine_Name and Prescription_Information are foreign keys referencing Medicine and Prescription respectively. The combination of Prescription_Information and Medicine_Name is the primary key of this table.
This schema ensures referential integrity by enforcing foreign key constraints. It allows us to track the relationship between different entities in the medical facility, such as doctors and patients, and the management of their respective data.
