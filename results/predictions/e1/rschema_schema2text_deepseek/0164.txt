The database schema named 'rschema_0164' consists of 6 tables. The database is used to manage and track various aspects of a warehouse environment.
The 'Warehouse' table represents the main entity in the schema. It contains information about each warehouse, including its creation date and time, update date, description, image path, location, name, and type. The 'Warehouse_ID' is the primary key for this table.
The 'User' table holds information about the users of the system. It includes details such as creation date and time, update date, email, password, phone number, role, and username. The 'User_ID' is the primary key for this table.
The 'Stack_Position' table represents the positions within the warehouse. It contains information about each position, including its belonging warehouse ID, creation date and time, description, image path, name, and type, and the update date. The 'Stack_Position_ID' is the primary key for this table, and the 'Belonging_Warehouse_ID' is a foreign key referencing the 'Warehouse_ID' in the 'Warehouse' table.
The 'Sensor' table holds information about the sensors in the warehouse. It contains details about the collected data value, collection time, data description, data status, sensor type, and the 'Stack_Position_ID' which is a foreign key referencing the 'Stack_Position_ID' in the 'Stack_Position' table.
The 'User_Operation_Stack_Position' table records the operations performed on the stack positions. It includes details about the operation description, operation time, operation type, operation user ID, and the 'Stack_Position_ID'. Both these fields are foreign keys referencing their respective tables. The combination of 'Operation_User_ID' and 'Stack_Position_ID' forms the primary key for this table.
Finally, the 'Stack_Position_Alert' table holds information about alerts related to the stack positions. It includes details about the alert description, alert level, alert status, alert time, alert type, and the 'Stack_Position_ID'. The 'Stack_Position_ID' is a foreign key referencing the 'Stack_Position_ID' in the 'Stack_Position' table. The combination of 'Stack_Position_ID' and 'Alert_Time' forms the primary key for this table.
This schema ensures domain integrity by ensuring that all fields allow null values and have default values where appropriate. It also ensures entity integrity by using primary and foreign keys to establish relationships between tables. The referential integrity is maintained by using CASCADE or RESTRICT rules on the foreign keys.
