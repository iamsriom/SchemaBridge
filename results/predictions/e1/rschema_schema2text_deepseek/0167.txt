The database schema named 'rschema_0167' consists of five tables: 'natural_disaster_data', 'region_information', 'department', 'user', and 'region_and_department'.
The 'natural_disaster_data' table holds data related to natural disasters. It includes columns for data id, data type, data source, upload time, data content, data format, and layer type. The data id is the primary key and is used to uniquely identify each record.
The 'region_information' table contains information about various regions. It includes columns for region id, region name, administrative division, latitude and longitude, area, and disaster risk level. The region id is the primary key and is used to identify each region.
The 'department' table holds information about various departments. It includes columns for department id, department name, person-in-charge, contact information, and functional scope. The department id is the primary key and is used to identify each department.
The 'user' table contains information about users. It includes columns for user id, username, role, contact information, permissions, and department id. The user id is the primary key and is used to identify each user. The department id is a foreign key referencing the department table, establishing a relationship between users and their respective departments.
Finally, the 'region_and_department' table acts as a junction table to link regions and departments. It includes columns for region id and department id, and also includes a column for division scope. Both region id and department id are foreign keys referencing the 'region_information' and 'department' tables respectively, establishing a relationship between regions and departments. The combination of department id and region id forms the primary key of this table, ensuring uniqueness of the record. The delete and update rules are set to cascade, meaning if a region or department is deleted or updated, the corresponding records in the 'region_and_department' table will also be deleted or updated.
