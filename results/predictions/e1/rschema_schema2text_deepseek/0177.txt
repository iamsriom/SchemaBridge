The database schema named 'rschema_0177' consists of three tables: Abstract_File, Directory, and File.
The Abstract_File table represents the abstract details of a file. It has five columns: Creation_Time (of type DATETIME), File_ID (of type INTEGER, acting as the primary key), Name (of type VARCHAR(255)), Type (of type VARCHAR(255)), and Update_Time (of type DATETIME).
The Directory table is linked to the Abstract_File table via the File_ID column, acting as a foreign key. It has two columns: Directory_ID (of type INTEGER, acting as the primary key) and Sub-file/directory_list (of type BLOB).
The File table is linked to both the Abstract_File and Directory tables via the Abstract_File_ID and Directory_ID columns, respectively, acting as foreign keys. It has seven columns: Abstract_File_ID (of type INTEGER, not null), Creation_Time (of type DATETIME), Directory_ID (of type INTEGER, not null), File_ID (of type INTEGER, acting as the primary key), File_Size (of type FLOAT), Name (of type VARCHAR(255)), Type (of type VARCHAR(255)), and Update_Time (of type DATETIME).
This schema ensures referential integrity by enforcing foreign key constraints. When a record in the Abstract_File table is deleted or updated, the corresponding records in the Directory and File tables will also be affected, as defined by the CASCADE delete or update rules.
