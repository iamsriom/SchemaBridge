The database schema named 'rschema_0201' comprises four tables: Level, Product, Member, and Shopping_Record.
The Level table represents the level of the user, with Level_ID as the primary key. It includes attributes such as Points_Range and Shopping_Frequency_Range, both of which are integers.
The Product table is used to store information about the products. Product_ID is the primary key and Product_Name is a variable character field that can store up to 255 characters.
The Member table represents the members of the user. Level_ID is a foreign key referencing the Level table, indicating the level of the member. Member_ID is the primary key, and Name, Phone_Number, and Points are other attributes, all of which are integers.
Lastly, the Shopping_Record table records the shopping records. Member_ID and Product_ID are foreign keys referencing the Member and Product tables respectively. Quantity, Shopping_Time, Store_ID, and Total_Price are other attributes. The primary key of this table is a composite key consisting of Member_ID, Product_ID, and Shopping_Time.
This schema ensures referential integrity by enforcing foreign key constraints. For instance, the Member table's Level_ID references the Level table's Level_ID, and the Shopping_Record table's Member_ID and Product_ID reference the Member and Product tables' respective primary keys.
The schema is designed to maintain entity integrity by ensuring that each table has a primary key and that the primary key is unique. The schema also allows for null values in some columns, but not all. For instance, the Member table's Level_ID column does not allow null values.
The schema also includes indexes on foreign keys to optimize the performance of the database.
In summary, this schema provides a comprehensive framework for managing a retail store's user levels, products, members, and shopping records.
