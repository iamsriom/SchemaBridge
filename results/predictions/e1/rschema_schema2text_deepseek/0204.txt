The database schema named 'rschema_0204' consists of four tables: 'participating_teams', 'referees', 'match_results', and 'events'.
The 'participating_teams' table represents the teams participating in an event. It has columns for team_id, team_name, team_size, team_members, team_leader_name, team_leader_phone, head_coach_name, and head_coach_phone. All these columns allow null values.
The 'referees' table holds information about the referees. It has columns for referee_id, referee_name, referee_gender, referee_email, and referee_phone. All these columns also allow null values.
The 'match_results' table records the results of the matches. It has columns for event_id, team_id, team_ranking, and referee_evaluation_result. The primary key is a composite key of team_id and event_id. The foreign keys are referencing the 'events' and 'referees' tables respectively. The ON DELETE and ON UPDATE rules are set to CASCADE, which means if the referenced record in the 'events' or 'referees' table is deleted or updated, the corresponding records in the 'match_results' table will also be deleted or updated.
Lastly, the 'events' table holds information about the events. It has columns for event_id, event_name, event_type, start_date, end_date, referee_id, and winning_team_id. The primary key is event_id. The foreign keys are referencing the 'events' and 'referees' tables respectively. The ON DELETE and ON UPDATE rules are set to CASCADE, which means if the referenced record in the 'events' or 'referees' table is deleted or updated, the corresponding records in the 'events' table will also be deleted or updated.
This schema ensures the integrity of the data by enforcing referential integrity through foreign keys and by setting cascading deletion and update rules.
