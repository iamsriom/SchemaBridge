The database schema named 'rschema_0257' contains four tables: 'Customer', 'Flight', 'Flight_Booking_Record', and 'Order'.
The 'Customer' table represents a customer of a travel agency. It contains columns for the customer's booking date, check-in time, check-out time, contact information, gender, ID, ID number, name, and type. The ID column is the primary key.
The 'Flight' table represents a flight. It contains columns for the airline name, arrival time, departure location, departure time, destination, flight date, flight ID, and flight name. The flight ID column is the primary key.
The 'Flight_Booking_Record' table represents a record of a booked flight. It contains columns for the booked flight ID, booking record ID, customer ID, discount rate, and ticket order number. The booked flight ID is a foreign key referencing the flight ID in the 'Flight' table.
Finally, the 'Order' table represents an order made by a customer. It contains columns for the customer ID, discount rate, order flight ID, order ID, and ticket order number. The customer ID is a foreign key referencing the customer ID in the 'Customer' table, and the order flight ID is a foreign key referencing the flight ID in the 'Flight' table.
This schema ensures referential integrity by enforcing foreign key constraints between the 'Customer', 'Flight', 'Flight_Booking_Record', and 'Order' tables. It also ensures entity integrity by ensuring that each record in the 'Customer' table has a unique ID and in the 'Flight' table, each flight has a unique ID. The 'Flight_Booking_Record' and 'Order' tables also maintain entity integrity by ensuring that each booking record and order has a unique ID. The schema also allows for update and delete cascades, meaning that if a record in the 'Flight' table is updated or deleted, the corresponding records in the 'Flight_Booking_Record' and 'Order' tables will also be updated or deleted.
