The database schema named 'rschema_0294' contains four tables: Branch_Office, Customer, Account, and Transaction_Record.
The Branch_Office table represents the branch offices of a bank. It has three columns: Address (a string of up to 255 characters), Branch_Office_ID (an integer, the primary key), and Name (a string of up to 255 characters).
The Customer table is used to store customer information. It has four columns: Contact_Phone_Number (an integer), Customer_ID (an integer, the primary key), Email_Address (a string of up to 255 characters), ID_Number (an integer), and Name (a string of up to 255 characters).
The Account table contains information about bank accounts. It has six columns: Account_Number (an integer, the primary key), Account_Type (a string of up to 255 characters), Balance (a float), Branch_Office_ID (an integer, not null, foreign key referencing Branch_Office), Customer_ID (an integer, not null, foreign key referencing Customer), and Open_Date (a datetime).
The Transaction_Record table records all transactions made in the bank. It has six columns: Account_Number (an integer, not null, foreign key referencing Account), Transaction_Amount (a float), Transaction_ID (an integer, the primary key), Transaction_Location (a string of up to 255 characters), Transaction_Time (a datetime), and Transaction_Type (a string of up to 255 characters).
This schema ensures referential integrity by enforcing foreign key constraints between the tables. It also ensures entity integrity by having primary keys in each table and unique constraints on certain columns. The schema is designed to maintain data integrity by ensuring that the data types of the columns match the data they are supposed to hold.
