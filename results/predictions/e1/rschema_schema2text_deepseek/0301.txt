The database schema named 'rschema_0301' consists of four tables: 'Seat_Template', 'User', 'Seat', and 'Seat_Template_Layout'.
The 'Seat_Template' table represents a template for seating arrangements. It has columns for 'description', 'template_ID', and 'template_name'. 'User' table stores user information including 'contact_number', 'email', 'name', and 'user_ID'.
The 'Seat' table represents a seat in the venue. It has columns for 'column', 'creation_time', 'flag', 'location_X', 'location_Y', 'price', 'reservedPurchasedUserID', 'row', 'seat_ID', 'type', and 'update_time'. The 'reservedPurchasedUserID' column does not allow null values and is a foreign key referencing the 'user_ID' in the 'User' table.
The 'Seat_Template_Layout' table represents the layout of the seating templates. It has columns for 'occasion', 'seat_ID', 'template_ID', and 'time_period'. Both 'seat_ID' and 'template_ID' are not null and are foreign keys referencing the 'seat_ID' in the 'Seat' table and the 'template_ID' in the 'Seat_Template' table, respectively. The combination of 'seat_ID' and 'template_ID' forms the primary key of this table.
The schema ensures referential integrity by enforcing foreign key constraints. If a record in the 'User' table is deleted, the corresponding records in the 'Seat' table will be deleted due to the 'CASCADE' rule. Similarly, if a record in the 'Seat' table is deleted, the corresponding records in the 'Seat_Template_Layout' table will be deleted due to the 'CASCADE' rule.
