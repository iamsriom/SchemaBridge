The database schema named 'rschema_0305' consists of four tables: 'user', 'post', 'notification', and 'follow'.
The 'user' table is used to store user account information. It contains six columns: 'account_id', 'name', 'email', 'password', 'verification_status', and 'account_status'. The 'account_id' column is the primary key, ensuring that each user has a unique identifier.
The 'post' table is used to store user posts. It contains five columns: 'post_id', 'publisher', 'content', 'publish_time', and 'attachment_link'. The 'post_id' column is the primary key, and the 'publisher' column is a foreign key referencing the 'account_id' in the 'user' table. This ensures that each post is associated with a valid user.
The 'notification' table is used to store notifications. It contains four columns: 'notification_id', 'recipient_user', 'notification_type', and 'notification_time'. The 'notification_id' column is the primary key, and the 'recipient_user' column is a foreign key referencing the 'account_id' in the 'user' table. This ensures that each notification is associated with a valid user.
The 'follow' table is used to store follow relationships between users. It contains two columns: 'user_account_1' and 'user_account_2'. Both columns are primary keys and foreign keys referencing the 'account_id' in the 'user' table. The combination of 'user_account_1' and 'user_account_2' forms a unique constraint, ensuring that each pair of users can only appear once in the table. This table represents the relationship between users, where 'user_account_1' is following 'user_account_2'. The ON DELETE CASCADE and ON UPDATE CASCADE options ensure that if a user account is deleted or updated, the corresponding follow relationships are also deleted or updated.
