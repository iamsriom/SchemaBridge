The database schema named 'rschema_0353' consists of five tables. The database is used for managing a web page system, with tables representing different entities involved in the system.
The 'page' table represents the web pages. It has columns for page_id, page_name, page_alias, page_title, display_order, style, redirection_target, click_event, hidden_or_not, page_group, and permission_schema. These columns hold the unique identifier for each page, the name, alias, title, display order, style, redirection target, click event, visibility status, page group, and permission schema of the page respectively. The primary key for this table is 'page_id'.
The 'user' table represents the users of the system. It has columns for user_id, username, and email_address. These columns hold the unique identifier for each user, the username, and email address of the user respectively. The primary key for this table is 'user_id'.
The 'administrator' table represents the administrators of the system. It has columns for administrator_id and administrator_name. These columns hold the unique identifier for each administrator and the name of the administrator respectively. The primary key for this table is 'administrator_id'.
The 'administrator_modifies_page' table represents the modifications made by administrators on the pages. It has columns for administrator_id, page_id, modification_time, and modification_content. These columns hold the unique identifier of the administrator, the unique identifier of the page, the time of modification, and the content of the modification respectively. The primary key for this table is a composite key of 'modification_time', 'page_id', and 'administrator_id'. The foreign keys 'administrator_id' and 'page_id' reference the 'administrator' and 'page' tables respectively. The delete and update rules are set to CASCADE, meaning that if a corresponding entry in the 'administrator' or 'page' tables is deleted or updated, the corresponding entries in the 'administrator_modifies_page' table will also be deleted or updated.
Finally, the 'user_access_page_record' table represents the access records of users on the pages. It has columns for user_id, page_id, and access_time. These columns hold the unique identifier of the user, the unique identifier of the page, and the time of access respectively. The primary key for this table is a composite key of 'user_id', 'access_time', and 'page_id'. The foreign keys 'user_id' and 'page_id' reference the 'user' and 'page' tables respectively. The delete and update rules are set to CASCADE, meaning that if a corresponding entry in the 'user' or 'page' tables is deleted or updated, the corresponding entries in the 'user_access_page_record' table will also be deleted or updated.
