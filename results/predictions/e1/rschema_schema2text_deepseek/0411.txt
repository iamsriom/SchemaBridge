The database schema named 'rschema_0411' contains three tables: 'Customer', 'Product', and 'Customer_product_purchase'.
The 'Customer' table represents a customer entity, with attributes such as 'Address', 'Contact_person', 'Credit_rating', 'Customer_ID', 'Customer_name', 'Customer_type', 'Email', and 'Phone'. The 'Customer_ID' is the primary key for this table, ensuring entity integrity as it uniquely identifies each customer.
The 'Product' table represents a product entity, with attributes such as 'Brand', 'Inventory_quantity', 'Product_ID', 'Product_category', 'Product_name', 'Production_date', 'Specifications', 'Supplier', and 'Unit_price'. The 'Product_ID' is the primary key for this table, ensuring entity integrity as it uniquely identifies each product.
The 'Customer_product_purchase' table represents a purchase made by a customer for a product. It has attributes such as 'Customer_ID', 'Order_status', 'Order_time', 'Payment_method', 'Payment_status', 'Payment_time', 'Product_ID', 'Product_quantity', 'Total_amount', and 'Unit_price'. The combination of 'Customer_ID' and 'Product_ID' and 'Order_time' form the primary key for this table, ensuring entity integrity as it uniquely identifies each purchase.
The 'Customer_ID' and 'Product_ID' are foreign keys referencing the 'Customer' and 'Product' tables respectively, ensuring referential integrity. The 'Customer_product_purchase' table allows null values for 'Order_status', 'Payment_method', and 'Payment_status', and has default values for 'Order_time' and 'Payment_time' if not provided. The database schema is designed to be flexible and allows for updates and deletions to cascade or restrict based on the specified rules.
