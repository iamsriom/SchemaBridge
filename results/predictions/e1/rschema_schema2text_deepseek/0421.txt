The database schema named 'rschema_0421' contains three tables: User, Property, and Rental_Transaction_Record.
The User table is used to store user information. It includes columns for Account_Creation_Time, Account_Update_Time, Email, Password, Phone_Number, Role, and User_ID. The User_ID is the primary key for this table.
The Property table is used to store property information. It includes columns for Images, Owner, Property_Area, Property_Creation_Time, Property_Description, Property_ID, Property_Location, Property_Title, Property_Update_Time, Rent, Status. The Property_ID is the primary key and the Owner column is a foreign key referencing the User_ID in the User table.
The Rental_Transaction_Record table is used to store rental transaction information. It includes columns for Lease_End_Date, Lease_Start_Date, Property_ID, Total_Rent, Transaction_Creation_Time, Transaction_Status, Transaction_Update_Time, and User_ID. The combination of User_ID, Property_ID, and Lease_Start_Date form the primary key for this table. The Property_ID is a foreign key referencing the Property_ID in the Property table, and the User_ID is a foreign key referencing the User_ID in the User table.
This schema ensures referential integrity by enforcing foreign key constraints. It also ensures entity integrity by ensuring that each record in the User table has a unique User_ID, and each record in the Property table has a unique Property_ID. The combination of User_ID, Property_ID, and Lease_Start_Date ensures that each rental transaction record is unique.
The schema is also designed to handle update and delete operations. When a record in the User, Property, or Rental_Transaction_Record table is updated or deleted, the database will automatically cascade the operation to related records in the Property and User tables. This ensures that the integrity of the data is maintained.
In summary, this schema is designed to manage user, property, and rental transaction data in a relational database system.
