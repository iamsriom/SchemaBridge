The database schema named "rschema_0425" contains 7 tables. The tables are described as follows:
1. **User**: This table represents the users of the system. It has columns for Password, Role, User_ID (which is the primary key), and Username. The User_ID is an integer and cannot be null.
2. **Building**: This table represents the buildings in the dormitory. It has columns for Building_ID (which is the primary key), Description, Dormitory_Supervisor_ID (which is a foreign key referencing User_ID), Location, Name, and Type. The Building_ID is an integer and cannot be null.
3. **Announcement**: This table represents the announcements in the system. It has columns for Administrator_ID (which is a foreign key referencing User_ID), Announcement_ID (which is the primary key), Content, Release_Time, and Title. The Administrator_ID and Announcement_ID are both integers and cannot be null.
4. **Dormitory**: This table represents the dormitories. It has columns for Building_ID (which is a foreign key referencing Building_ID), Dormitory_ID (which is the primary key), Facilities, Name, Number_of_Beds, and Type. The Building_ID and Dormitory_ID are both integers and cannot be null.
5. **Student**: This table represents the students. It has columns for Class, Dormitory_ID (which is a foreign key referencing Dormitory_ID), Gender, Name, Student_ID (which is the primary key), and Dormitory_ID is an integer and cannot be null.
6. **Maintenance_Record**: This table represents the maintenance records. It has columns for Completion_Time, Dormitory_ID (which is a foreign key referencing Dormitory_ID), Fault_Description, Maintenance_ID (which is the primary key), Maintenance_Staff_ID (which is a foreign key referencing User_ID), Maintenance_Status, and Report_Time. The Dormitory_ID and Maintenance_ID are both integers and cannot be null.
7. **Application**: This table represents the applications. It has columns for Application_Content, Application_ID (which is the primary key), Application_Time, Application_Type, Processing_Opinion, Processing_Status, and Student_ID (which is a foreign key referencing Student_ID). The Application_ID and Student_ID are both integers and cannot be null.
This schema ensures referential integrity by enforcing foreign key constraints. For instance, the Building table references the User table through Dormitory_Supervisor_ID, the Announcement table references the User table through Administrator_ID, the Dormitory table references the Building table through Building_ID, the Student table references the Dormitory table through Dormitory_ID, the Maintenance_Record table references both the User table through Maintenance_Staff_ID and the Dormitory table through Dormitory_ID, and the Application table references the Student table through Student_ID.
