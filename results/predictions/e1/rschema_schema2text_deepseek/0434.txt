The database schema named rschema_0434 consists of five tables: User, Maze, Skybox, Map, and User_Game_Record.
The User table is used to store user information. It contains five columns: Email (a string of up to 255 characters), Password (also a string of up to 255 characters), Registration_Time (a date and time), User_ID (an integer), and Username (a string of up to 255 characters). The User_ID is the primary key of this table.
The Maze table is used to store maze information. It contains five columns: Creation_Date (a date and time), Description (a string of up to 255 characters), Last_Modified_Date (a date and time), Maze_ID (an integer), and Name (a string of up to 255 characters). The Maze_ID is the primary key of this table.
The Skybox table is used to store skybox information. It contains six columns: Creation_Date (a date and time), Description (a string of up to 255 characters), File_Path (a string of up to 255 characters), Last_Modified_Date (a date and time), Name (a string of up to 255 characters), and Skybox_ID (an integer). The Skybox_ID is the primary key of this table.
The Map table is used to store map information. It contains six columns: Associated_Maze_ID (an integer), Creation_Date (a date and time), Last_Modified_Date (a date and time), Map_Data (a binary large object), Map_ID (an integer), and Name (a string of up to 255 characters). The Map_ID is the primary key of this table, and the Associated_Maze_ID is a foreign key referencing the Maze table.
Finally, the User_Game_Record table is used to store user game records. It contains nine columns: Game_Creation_Time (a date and time), Game_End_Time (a date and time), Game_Last_Modified_Time (a date and time), Game_Start_Time (a date and time), Game_Status (a string of up to 255 characters), Maze_ID (an integer), User_ID (an integer), User_Score (an integer), and the combination of User_ID and Maze_ID is the primary key. The Maze_ID and User_ID are foreign keys referencing the Maze and User tables, respectively.
This schema ensures data integrity by enforcing primary and foreign key constraints, and by allowing null values in some columns. It also includes indexes on the foreign keys to optimize database performance.
