The database schema named 'rschema_0466' consists of four tables: 'Customer', 'Employee', 'Menu', and 'Customer_Order'.
The 'Customer' table represents a customer entity with attributes including 'Address', 'Contact_Number', 'Customer_ID', 'Name', and 'Payment_Method'. It has a primary key 'Customer_ID' that uniquely identifies each customer.
The 'Employee' table represents an employee entity with attributes including 'Contact_Number', 'Employee_ID', 'Name', and 'Position'. It has a primary key 'Employee_ID' that uniquely identifies each employee.
The 'Menu' table represents a menu entity with attributes including 'Dish_Name' and 'Menu_ID' and 'Price'. It has a primary key 'Menu_ID' that uniquely identifies each menu item.
The 'Customer_Order' table represents a customer order entity with attributes including 'Customer_ID', 'Delivery_Location', 'Delivery_Time', 'Menu_ID', 'Order_Quantity', 'Order_Status', and 'Order_Time'. It has a composite primary key consisting of 'Customer_ID', 'Menu_ID', and 'Order_Time' that uniquely identifies each order. The 'Customer_ID' and 'Menu_ID' are foreign keys referencing the 'Customer' and 'Menu' tables respectively. The 'Order_Status' column allows null values and has a default value of 'Pending'.
This schema ensures referential integrity as the 'Customer_Order' table references the 'Customer' and 'Menu' tables. The 'Customer_ID' in 'Customer_Order' table is set to CASCADE on delete and update, meaning if a customer is deleted or updated, the corresponding orders will also be affected. Similarly, the 'Menu_ID' in 'Customer_Order' table is set to RESTRICT, meaning if a menu item is deleted, the corresponding orders will not be affected.
