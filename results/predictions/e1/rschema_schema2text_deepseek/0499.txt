The database schema named "rschema_0499" consists of five tables: Class, Sports_team, Dormitory, Student, and Team_membership.
The Class table represents the classes offered by the school. It has an integer primary key, Class_ID, and four columns: Class_name, Classroom, Major, and Major. All columns allow null values.
The Sports_team table represents the sports teams. It has an integer primary key, Team_ID, and three columns: Activity_time, Coach, and Team_name. All columns allow null values.
The Dormitory table represents the dormitories. It has two integer columns: Building_number and Dormitory_number, which together form the primary key. It also has an integer column Number_of_residents.
The Student table represents the students. It has an integer primary key, Student_ID, and four integer columns: Age, Building_number, Class_ID, and Dormitory_number. It also has a boolean column Gender and a varchar column Name. All columns except Building_number, Class_ID, and Dormitory_number allow null values. The Building_number, Class_ID, and Dormitory_number columns are foreign keys referencing the Building_number, Class_ID, and Dormitory_number columns of the Dormitory table respectively.
The Team_membership table represents the team memberships. It has two integer columns: Student_ID and Team_ID, which together form the primary key. Both columns are foreign keys referencing the Student_ID and Team_ID columns of the Student and Sports_team tables respectively.
This schema ensures referential integrity by enforcing foreign key constraints. When a record in the Dormitory table is deleted or updated, the corresponding records in the Student table will be automatically updated or deleted due to the cascade delete or update rules. Similarly, when a record in the Class or Sports_team table is deleted or updated, the corresponding records in the Student or Team_membership table will be automatically updated or deleted.
