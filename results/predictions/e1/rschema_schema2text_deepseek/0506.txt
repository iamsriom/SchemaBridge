The database schema for the 'rschema_0506' database is described below.
The database is composed of 11 tables. The primary key (PK) and foreign key (FK) relationships are shown in the table below.
1. `construction_management_unit`: This table contains information about the construction management units. The primary key is `unit_id`. The foreign key `supervision_department_id` references `collaborative_task`.
2. `business_project_department_progress`: This table records the progress of the business project departments. The primary key is `project_department_id`.
3. `resource_allocation`: This table manages resource allocation for projects. The primary key is a composite of `resource_id` and `project_id`. The foreign keys `resource_id` and `project_id` reference `resource_table` and `supervision_project_department` respectively.
4. `collaborative_task`: This table manages collaborative tasks. The primary key is a composite of `task_id` and `project_id`. The foreign keys `task_id` and `project_id` reference `collaborative_work_platform` and `supervision_project_department` respectively.
5. `supervision_project_department`: This table records the supervision project department information. The primary key is `supervision_department_id`.
6. `electrical_grid_infrastructure_project`: This table contains information about the electrical grid infrastructure projects. The primary key is `project_id`. The foreign keys `task_id`, `unit_id`, and `project_department_id` reference `collaborative_work_platform`, `construction_management_unit`, and `business_project_department_progress` respectively.
7. `resource_table`: This table contains information about the resources. The primary key is `resource_id`.
8. `collaborative_work_platform`: This table manages the collaborative work platform. The primary key is `task_id`.
9. `project_management`: This table manages the project management. The primary key is a composite of `unit_id` and `project_id`. The foreign keys `unit_id` and `project_id` reference `construction_management_unit` and `supervision_project_department` respectively.
10. `project_department_management`: This table manages the project department management. The primary key is a composite of `project_id` and `project_department_id`. The foreign keys `project_id` and `project_department_id` reference `supervision_project_department` and `business_project_department_progress` respectively.
11. `supervision_department_management`: This table manages the supervision department management. The primary key is a composite of `supervision_department_id` and `project_id`. The foreign keys `supervision_department_id` and `project_id` reference `collaborative_task` and `supervision_project_department` respectively.
All tables allow null values except for the NOT NULL constraints. The database follows referential integrity constraints, where deletion or update operations are cascaded to the related tables.
