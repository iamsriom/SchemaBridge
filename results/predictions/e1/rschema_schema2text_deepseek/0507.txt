The database schema for the database named 'rschema_0507' consists of 7 tables. The database is used to manage user accounts, authentication tokens, content creation, and video content.
The 'user' table represents the users of the system. It has columns for 'user_id', 'user_name', 'password', and 'role'. The 'user_id' column is the primary key.
The 'token' table stores authentication tokens. It has columns for 'public_key', 'private_key', 'generation_time', and 'bound_user'. The 'public_key' is the primary key and is also a foreign key referencing the 'user_id' in the 'user' table.
The 'content' table is used to store content information. It has columns for 'content_id', 'title', 'type', 'creation_time', 'update_time', and 'created_by_user'. The 'content_id' is the primary key and is also a foreign key referencing the 'user_id' in the 'user' table.
The 'image_text_content' table stores image and text content. It has columns for 'content_id' and 'image_text_link'. The 'content_id' is the primary key and is also a foreign key referencing the 'content_id' in the 'content' table.
The 'video_content' table stores video content. It has columns for 'content_id' and 'video_link'. The 'content_id' is the primary key and is also a foreign key referencing the 'content_id' in the 'content' table. The 'video_link' is also a foreign key referencing the 'video_link' in the 'video_information' table.
The 'video_information' table stores video information. It has columns for 'video_link', 'thumbnail_url', and 'video_duration'. The 'video_link' is the primary key.
Finally, the 'video_play_count_record' table stores video play count records. It has columns for 'video_link', 'record_time', and 'play_count'. The combination of 'video_link' and 'record_time' is the primary key and is also a foreign key referencing the 'video_link' in the 'video_information' table.
All columns allow null values and have default values if not specified. The database is set up to maintain referential integrity by cascading deletions and updates.
