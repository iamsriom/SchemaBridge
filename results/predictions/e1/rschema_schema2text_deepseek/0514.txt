The database schema named 'rschema_0514' consists of three tables: 'Customer', 'Account', and 'Transaction'.
The 'Customer' table represents the customers of a bank. It has five columns: 'Account_Opening_Date' of type DATETIME, 'Contact_Number' of type VARCHAR(255), 'Customer_ID' of type INTEGER as the primary key, 'Email' of type VARCHAR(255), and 'Name' of type VARCHAR(255).
The 'Account' table represents the bank accounts of the customers. It has four columns: 'Account_ID' of type INTEGER as the primary key, 'Balance' of type VARCHAR(255), 'Customer_ID' of type INTEGER, which is a foreign key referencing the 'Customer_ID' in the 'Customer' table.
The 'Transaction' table represents the transactions made by the customers. It has six columns: 'Customer_ID' of type INTEGER, which is a foreign key referencing the 'Customer_ID' in the 'Customer' table, 'Transaction_Amount' of type INTEGER, 'Transaction_ID' of type INTEGER as the primary key, 'Transaction_Status' of type VARCHAR(255), 'Transaction_Time' of type DATETIME, and 'Transaction_Type' of type VARCHAR(255).
Each table has been designed with entity integrity in mind, with primary keys and foreign keys ensuring that the relationships between tables are maintained. The 'Customer' table has no null values and allows for composite or unique constraints. The 'Account' and 'Transaction' tables allow null values, but they have foreign key constraints to ensure that the 'Customer_ID' values exist in the 'Customer' table. The foreign key constraints also have update and delete rules set to CASCADE or RESTRICT, which means if a record in the 'Customer' table is updated or deleted, the corresponding records in the 'Account' and 'Transaction' tables will also be updated or deleted.
