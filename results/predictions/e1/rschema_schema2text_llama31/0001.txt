The rschema_0001 database is designed to manage information about airplanes, their crews, and the flights they operate. The database contains three main tables: Airplane, Crew, and Flight. The Airplane table represents individual airplanes, with attributes such as Airplane_Number, which is a unique identifier and the primary key, Model, which describes the type of airplane, and Passenger_Capacity, which indicates the maximum number of passengers the airplane can carry. The Crew table stores information about the personnel involved in flights, including Name, Personnel_ID, which is a unique identifier and the primary key, and Phone_Number, which is the contact information for the crew member. The Flight table represents individual flights, with attributes such as Airplane_Number, Arrival_Time, Departure_Time, Destination, End_Time, First_Officer_ID, Flight_Number, Origin, and Start_Time. The domain integrity of the database is ensured through various constraints: Airplane_Number in the Flight table cannot be null, and all attributes in the Crew table cannot be null. The entity integrity of the database is maintained through primary keys, which uniquely identify each airplane and each flight, and composite keys, which are not present in this schema. The referential integrity of the database is ensured through foreign keys, which link the Flight table to the Airplane and Crew tables, indicating that each flight is associated with a specific airplane and two crew members, the captain and the first officer. The foreign key constraints also specify that when an airplane or a crew member is deleted, all associated flights will be deleted as well, which is known as a cascade delete rule.
