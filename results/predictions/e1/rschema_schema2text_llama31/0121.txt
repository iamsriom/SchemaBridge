The rschema_0121 database is designed to manage user authentication, services, and their interactions. At its core, the database contains a table called 'user' which stores information about each registered user, including their unique identifier, username, full name, email, password hash, registration date, and last login date. Each user can be associated with an 'authenticated_user' table, which tracks their authentication level, signature, issuer, and authentication time. The 'service' table stores details about the services available, including their unique identifier, name, type, URL, configuration data, last heartbeat time, monitoring status, signature, and issuer. Worker nodes, which are essentially machines that run these services, are stored in the 'worker_node' table, which includes their unique identifier, name, status, service ID, operating system, architecture, last heartbeat time, signature, and issuer. The 'authenticated_consumer' table links users to their associated consumers, which are essentially applications or entities that use these services, and includes information such as the consumer's ID, user ID, name, description, type, configuration data, permissions, signature, and issuer. The 'user_migration' table tracks user ID changes over time, including the old and new user IDs, migration time, and a unique migration ID. Sessions, which are essentially temporary connections between consumers and services, are stored in the 'session' table, which includes the session ID, consumer ID, expiration time, MFA status, signature, and issuer. Finally, the 'encrypted_data_test' table stores sensitive data, including regular data, sensitive data 1 and 2, signature, and issuer, with a unique data ID. Throughout the database, foreign keys are used to establish relationships between tables, such as the 'authenticated_user' table referencing the 'user' table, and the 'session' table referencing the 'authenticated_consumer' table, with cascade delete and update rules applied to ensure data consistency.
