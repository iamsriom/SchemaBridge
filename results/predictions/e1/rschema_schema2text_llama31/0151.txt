The rschema_0151 database is designed to manage information about customers and their transactions with savings institutions. The Customer table stores details about each individual customer, including their name, phone number, and identity card number, which serves as the primary key to uniquely identify each customer. The Address column is also included, although it does not have a primary key constraint. The Savings_Institution table contains information about the savings institutions, such as their name, phone number, and address, with the Savings_Institution_ID being the primary key. The Transaction_Record table tracks the transactions between customers and savings institutions, including the transaction amount, interest rate, maturity date, and transaction time. This table has a composite primary key consisting of the customer's identity card number, the savings institution's ID, and the transaction time. The Identity_Card_Number column in the Transaction_Record table references the Identity_Card_Number in the Customer table, and the Savings_Institution_ID column references the Savings_Institution_ID in the Savings_Institution table, establishing relationships between these entities. The Identity_Card_Number column in the Transaction_Record table does not allow null values, while the Savings_Institution_ID column also does not allow null values. The Address column in both the Customer and Savings_Institution tables does not have any constraints, and the Password column in the Transaction_Record table does not have any constraints either.
