The rschema_0205 database is used to store information about performances and the actors involved. The performance_event table contains details about each event, including its unique identifier, name, time, and location. Each performance event is uniquely identified by its performance_event_id, which cannot be null. The actor table stores information about the individuals performing, with each actor having a unique actor_id. The performance_list table links actors to the performances they participate in, with each entry consisting of an actor's identifier and the corresponding performance event's identifier. The performance_list table has a composite primary key consisting of both the actor_id and performance_event_id, ensuring that each actor can only be associated with a performance once. The performance_list table also has two foreign keys referencing the actor and performance_event tables, with the performance_event_id referencing the performance_event_id in the performance_event table and the actor_id referencing the actor_id in the actor table. The performance_event_id in the performance_list table is set to cascade delete and update, meaning that if a performance event is deleted or updated, all associated entries in the performance_list table will be automatically deleted or updated.
