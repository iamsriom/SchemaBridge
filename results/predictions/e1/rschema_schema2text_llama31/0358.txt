The rschema_0358 database is designed to manage scheduled tasks and their associated execution instances. The database contains two tables: scheduled_task and execution_instance. The scheduled_task table stores information about each scheduled task, including its unique identifier, revision number, type, lock expiration time, lock owner, and various configuration details such as execution ID, process instance ID, process definition ID, retries, exception stack ID, exception message, due date, repeat frequency, handler type, and handler configuration. The tenant ID is also stored, which likely identifies the organization or user associated with the task. The primary key for this table is the unique task ID, and it has foreign key relationships with the execution_instance table, specifically referencing the execution ID and process instance ID columns. The execution_instance table stores information about the execution of a process, including its unique execution ID, process instance ID, and process definition ID. The primary key for this table is the execution ID. The scheduled_task table has foreign key relationships with the execution_instance table, where the execution ID and process instance ID columns reference the execution ID and process instance ID columns in the execution_instance table, with both relationships set to cascade on delete and update, meaning that if a related record in the execution_instance table is deleted or updated, the corresponding record in the scheduled_task table will also be deleted or updated.
