The rschema_0429 database is designed to manage a restaurant's operations, storing information about users, menu items, orders, and order details. The user table contains essential information about each customer, including their username, password, and role, with the username serving as the primary key to uniquely identify each user. The dish table holds details about the menu items, such as the dish name, price, category, and availability, with the dish name being the primary key. The order table tracks each customer's orders, including the order ID, the username of the ordering user, the order time, the total order amount, and the order status, with the order ID being the primary key and the ordering user ID referencing the username in the user table with a cascade delete and update rule to ensure that an order is automatically deleted or updated if the associated user is deleted or updated. The order detail table contains additional information about each order, including the order detail ID, the order ID, the dish ID, and the quantity of each dish ordered, with the order detail ID being the primary key and both the order ID and dish ID referencing the corresponding tables with cascade delete and update rules to ensure that an order detail is automatically deleted or updated if the associated order or dish is deleted or updated.
