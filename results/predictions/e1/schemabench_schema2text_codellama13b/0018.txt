This schema is for a monitoring system that tracks the status of various services and instances. It includes tables for users, services, instances, and status checks, as well as tables for tracking alerts and notifications. The schema is designed to be flexible and scalable, with many-to-many relationships between tables and foreign keys to ensure data integrity.
The `user` table contains information about the users who have access to the monitoring system, including their username, email, and password. The `service` table contains information about the services being monitored, including their name, alerts enabled status, and other metadata. The `instance` table contains information about the instances of those services, including their name, alerts enabled status, and other metadata.
The `status_check` table contains information about the status checks that are run on the services and instances, including the name, frequency, and importance of the check. The `status_check_result` table contains the results of the status checks, including whether they succeeded or failed, and any error messages.
The `alert_acknowledgement` table contains information about alerts that have been acknowledged by users, including the time the alert was acknowledged and the user who acknowledged it. The `alert_plugin` table contains information about the alert plugins that are used to send notifications, including the title, enabled status, and other metadata.
The `alert_plugin_user_data` table contains information about the user data associated with alert plugins, including the title, user ID, and other metadata. The `instance_status_snapshot` table contains information about the status of instances at a given time, including the number of checks active, passing, and failing, as well as the overall status. The `service_status_snapshot` table contains information about the status of services at a given time, including the number of checks active, passing, and failing, as well as the overall status.
The `shift` table contains information about the shifts that users are on, including the start and end times, user ID, and other metadata. The `user_profile` table contains information about the user profiles, including the mobile number, hipchat alias, and other metadata. The `service_status_check` table contains information about the status checks that are run on services, including the service ID and status check ID. The `service_user` table contains information about the users who have access to services, including the service ID and user ID.
The `instance_status_check` table contains information about the status checks that are run on instances, including the instance ID and status check ID. The `instance_users` table contains information about the users who have access to instances, including the instance ID and user ID. The `jenkins_status_check` table contains information about the status checks that are run on Jenkins, including the Jenkins configuration ID and status check ID. The `jenkins_config` table contains information about the Jenkins configurations, including the name, Jenkins API, user, and password.
Overall, this schema is designed to provide a flexible and scalable framework for tracking the status of various services and instances, as well as sending alerts and notifications to users. It is organized into several tables, each with its own specific purpose and relationships with other tables in the schema.
