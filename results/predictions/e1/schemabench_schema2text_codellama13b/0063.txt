The larametrics_logs table contains information about log messages generated by the application, including the log level, message, user ID, email, trace, and timestamps. The table has a primary key on the id column and a foreign key on the user_id column that references the users table.
The larametrics_models table contains information about the models used in the application, including the model name, model ID, user ID, method, original data, and changes. The table has a primary key on the id column and a foreign key on the user_id column that references the users table.
The larametrics_notifications table contains information about notifications sent by the application, including the action, filter, meta data, notify by, and timestamps. The table has a primary key on the id column.
The larametrics_requests table contains information about HTTP requests made to the application, including the method, URI, IP address, headers, start time, end time, and timestamps. The table has a primary key on the id column.
The users table contains information about the users of the application, including their ID. The table has a primary key on the id column.
The foreign key constraints ensure referential integrity between the tables, ensuring that the data in the tables is consistent and accurate. For example, the foreign key on the user_id column in the larametrics_logs and larametrics_models tables references the users table, ensuring that the user ID in those tables corresponds to a valid user in the users table. Similarly, the foreign key on the user_id column in the larametrics_notifications table references the users table, ensuring that the user ID in that table corresponds to a valid user in the users table.
