The schemabench_0065 database contains 14 tables that store information related to PayPal transactions and agreements. The tables are:
1. djpaypal_billingagreement: This table stores information about PayPal billing agreements, including the agreement ID, name, state, description, agreement details, payer, shipping address, override merchant preferences, override charge mode, plan, merchant, payer model ID, user ID, plan model ID, livemode, created date, updated date, start date, and end of period.
2. djpaypal_billingplan: This table stores information about PayPal billing plans, including the plan ID, livemode, created date, updated date, name, description, type, state, create time, update time, and merchant preferences.
3. djpaypal_billingplan_payment_definitions: This table stores information about the payment definitions associated with a billing plan, including the payment definition ID, billing plan ID, and payment definition ID.
4. djpaypal_chargemodel: This table stores information about PayPal charge models, including the charge model ID, livemode, created date, updated date, type, and amount.
5. djpaypal_dispute: This table stores information about PayPal disputes, including the dispute ID, livemode, created date, updated date, create time, update time, disputed transactions, reason, status, dispute amount, dispute outcome, messages, seller response due date, dispute flow, dispute channel, and dispute life cycle stage.
6. djpaypal_payer: This table stores information about PayPal payers, including the payer ID, first name, last name, email, shipping address, livemode, created date, updated date, user ID, and time created.
7. djpaypal_payment: This table stores information about PayPal payments, including the payment ID, livemode, created date, updated date, intent, cart, payer, transactions, state, experience profile ID, note to payer, create time, update time, redirect URLs, and failure reason.
8. djpaypal_paymentdefinition: This table stores information about PayPal payment definitions, including the payment definition ID, livemode, created date, updated date, name, type, frequency interval, frequency, cycles, and amount.
9. djpaypal_paymentdefinition_charge_models: This table stores information about the charge models associated with a payment definition, including the payment definition ID, charge model ID, and payment definition ID.
10. djpaypal_preparedbillingagreement: This table stores information about prepared billing agreements, including the prepared agreement ID, livemode, data, executed at, canceled at, created, updated, executed agreement ID, user ID, and prepared agreement ID.
11. djpaypal_refund: This table stores information about PayPal refunds, including the refund ID, livemode, created date, updated date, amount, state, reason, invoice number, description, create time, update time, reason code, refund reason code, refund funding type, parent payment ID, sale ID, refund from received amount, refund from transaction fee, total refunded amount, refund to payer, and sale ID.
12. djpaypal_sale: This table stores information about PayPal sales, including the sale ID, livemode, created date, updated date, amount, payment mode, state, reason code, protection eligibility, protection eligibility type, clearing time, transaction fee, receivable amount, exchange rate, FMF details, receipt ID, processor response, create time, update time, soft descriptor, billing agreement ID, parent payment ID, invoice number, payment hold reasons, payment hold status, and sale ID.
13. djpaypal_webhookevent: This table stores information about PayPal webhook events, including the event ID, livemode, created date, updated date, event version, create time, event type, resource type, resource, status, summary, and transmissions.
14. djpaypal_webhookeventtrigger: This table stores information about PayPal webhook event triggers, including the trigger ID, remote IP, headers, body, valid, processed, exception, traceback, djpaypal version, created date, updated date, and webhook event ID.
Each table has its own set of columns, with some tables having foreign keys that reference other tables in the schema. The tables are related to each other through the foreign keys, which ensure referential integrity and entity integrity in the database.
