The schemabench_0171 database is used to store information about financial trades and their related entities. The database contains six tables, each representing a different aspect of the trades.
The first table, "audit," stores information about the activities that have been performed on the trades. It has four columns: "AuditID," which is the primary key and an auto-incrementing integer; "TradeID," which is a foreign key referencing the "trades" table; "Activity," which is a string describing the activity that was performed; and "ActivityTimestamp," which is a timestamp of when the activity was performed.
The second table, "counterparties," stores information about the counterparties involved in the trades. It has five columns: "TradeID," which is a foreign key referencing the "trades" table; "CounterpartyID," which is a unique identifier for the counterparty; "CounterpartyName," which is the name of the counterparty; "ExposureLimit," which is the maximum amount of exposure the counterparty is allowed to have; and "Primary Key," which is a composite key made up of "TradeID" and "CounterpartyID."
The third table, "instrument," stores information about the financial instruments involved in the trades. It has eight columns: "InstrumentID," which is the primary key and an auto-incrementing integer; "InstrumentLabel," which is a string describing the instrument; "TradeID," which is a foreign key referencing the "trades" table; "MaturityDate," which is the date the instrument matures; "SettlementType," which is the type of settlement for the instrument; "Currency," which is the currency in which the instrument is denominated; and "Foreign Key," which is a foreign key referencing the "trades" table.
The fourth table, "trader," stores information about the traders involved in the trades. It has four columns: "TraderID," which is the primary key and an auto-incrementing integer; "TraderName," which is the name of the trader; "TraderEmail," which is the email address of the trader; and "TradeID," which is a foreign key referencing the "trades" table.
The fifth table, "trades," stores information about the trades themselves. It has 14 columns: "TradeID," which is the primary key and an auto-incrementing integer; "Portfolio," which is the portfolio in which the trade is placed; "TradeDate," which is the date the trade was executed; "InstrumentID," which is a foreign key referencing the "instrument" table; "Quantity," which is the quantity of the instrument traded; "Price," which is the price at which the trade was executed; "Typology," which is the typology of the trade; "CounterpartyID," which is a foreign key referencing the "counterparties" table; "TraderID," which is a foreign key referencing the "trader" table; "Notional," which is the notional amount of the trade; "FixedRate," which is the fixed rate for the trade; "FloatRateIndex," which is the float rate index for the trade; and "Spread," which is the spread for the trade.
The sixth table, "tradestatus," stores information about the status of the trades. It has three columns: "TradeID," which is a foreign key referencing the "trades" table; "StatusID," which is a unique identifier for the status; and "StatusName," which is the name of the status.
In summary, the schemabench_0171 database is used to store information about financial trades and their related entities, including audit activities, counterparties, instruments, traders, trades, and trade statuses. Each table has its own set of columns, and there are foreign key relationships between the tables to ensure referential integrity.
