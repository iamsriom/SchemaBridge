The customer_nodes table has a composite primary key, consisting of customer_id and node_id, which together uniquely identify each customer-node relationship. The customer_transactions table has a single primary key, customer_id, which is an integer that uniquely identifies each customer.
In addition to the primary keys, each table has unique constraints that ensure the integrity of the data. The customer_transactions table has a unique constraint on the combination of customer_id and txn_date, which ensures that each customer can only have one transaction on a given date.
The foreign keys in the customer_nodes and customer_transactions tables reference the primary keys in the regions and customer_nodes tables, respectively. The update and delete rules for these foreign keys are CASCADE, which means that if a row in the regions or customer_nodes table is updated or deleted, the corresponding rows in the customer_nodes or customer_transactions table will be updated or deleted as well.
