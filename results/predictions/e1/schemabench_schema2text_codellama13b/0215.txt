The schemabench_0215 database contains seven tables that work together to model a fictional airline company. The tables are:
1. PASSENGER: This table stores information about the passengers, including their account ID, name, age, and frequent flyer ID. The account ID is the primary key and is not null.
2. AIRPORT: This table stores information about the airports, including their code, name, city, state, address, classification, and time zone. The airport code is the primary key and is not null.
3. AIRCRAFT: This table stores information about the aircraft, including their number, make, weight limit, flight number, and airport code. The airplane number is the primary key and is not null.
4. FLIGHTCREW: This table stores information about the flight crew, including their employee ID, name, title, age, street address, zip code, city, state, and airport code. The employee ID is the primary key and is not null.
5. FLIGHT: This table stores information about the flights, including their flight number, departure time, arrival time, flight price, airport code, gate number, airplane number, and employee ID. The flight number is the primary key and is not null.
6. TICKET: This table stores information about the tickets, including the ticket ID, from location, to location, seat, price, flight status, class, account ID, and flight number. The ticket ID is the primary key and is not null.
7. LUGGAGE: This table stores information about the luggage, including the luggage ID, carousel number, weight, account ID, and airplane number. The luggage ID is the primary key and is not null.
The tables are related to each other through foreign keys, which enforce referential integrity. For example, the FLIGHTCREW table has a foreign key to the AIRPORT table, which ensures that the airport code in the FLIGHTCREW table is valid. Similarly, the FLIGHT table has foreign keys to the AIRCRAFT and FLIGHTCREW tables, which ensure that the airplane number and employee ID in the FLIGHT table are valid.
The tables also have primary keys, which ensure that each row in the table is unique. The primary keys are used to identify the rows in the table and to enforce entity integrity.
In summary, the schemabench_0215 database schema models a fictional airline company, with tables for passengers, airports, aircraft, flight crew, flights, tickets, and luggage. The tables are related to each other through foreign keys, which enforce referential integrity, and have primary keys, which ensure that each row in the table is unique.
