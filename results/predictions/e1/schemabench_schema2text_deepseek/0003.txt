The database schema named "schemabench_0003" consists of 12 tables. The primary function of this schema is to manage user and team-related data, including user profiles, team information, announcements, API tokens, invitations, invoices, notifications, password resets, performance indicators, subscriptions, team subscriptions, and team users.
The "users" table contains user information including id, name, email, email verification status, password, remember token, photo URL, two-factor authentication status, Authy ID, country code, phone number, Stripe ID, two-factor reset code, current team ID, current billing plan, card brand, card last four digits, card country, billing address, billing address line 2, billing city, billing state, billing zip code, billing country, VAT ID, extra billing information, trial end date, last read announcements date, and creation and update timestamps.
The "teams" table contains team information including id, owner id, name, slug, photo URL, Stripe ID, current billing plan, card brand, card last four digits, card country, billing address, billing address line 2, billing city, billing state, billing zip code, billing country, VAT ID, extra billing information, trial end date, and creation and update timestamps. It also has a foreign key relationship with the "users" table, linking the owner of the team to a user in the "users" table.
The "announcements" table contains announcement information including id, user id, body, action text, action URL, and creation and update timestamps. It also has a foreign key relationship with the "users" table, linking the author of the announcement to a user in the "users" table.
The "api_tokens" table contains API token information including id, user id, name, token, metadata, transient status, last used date, expiry date, and creation and update timestamps. It also has a foreign key relationship with the "users" table, linking the owner of the API token to a user in the "users" table.
The "invitations" table contains invitation information including id, team id, user id, role, email, token, and creation and update timestamps. It also has foreign key relationships with both the "users" and "teams" tables, linking the inviting user and team to their respective entries in the "users" and "teams" tables.
The "invoices" table contains invoice information including id, user id, team id, provider id, total, tax, card country, billing state, billing zip code, billing country, VAT ID, and creation and update timestamps. It also has foreign key relationships with both the "users" and "teams" tables, linking the invoice to a user or team in the "users" or "teams" tables.
The "notifications" table contains notification information including id, user id, icon, body, action text, action URL, read status, and creation and update timestamps. It also has a foreign key relationship with the "users" table, linking the recipient of the notification to a user in the "users" table.
The "password_resets" table contains password reset information including email, token, and creation date.
The "performance_indicators" table contains performance indicator information including id, monthly recurring revenue, yearly recurring revenue, daily volume, new users, and creation and update timestamps.
The "subscriptions" table contains subscription information including id, user id, name, Stripe ID, Stripe plan, Stripe status, quantity, trial end date, end date, and creation and update timestamps. It also has a foreign key relationship with the "users" table, linking the subscriber to a user in the "users" table.
The "team_subscriptions" table contains team subscription information including id, team id, name, Stripe ID, Stripe plan, Stripe status, quantity, trial end date, end date, and creation and update timestamps. It also has a foreign key relationship with the "teams" table, linking the team subscription to a team in the "teams" table.
The "team_users" table contains team user information including team id, user id, and role. It also has foreign key relationships with both the "users" and "teams" tables, linking a user to a team and specifying their role within the team.
All tables allow null values except for the ones that are marked as NOT NULL, which ensures data integrity and entity integrity. Primary keys are used to uniquely identify each record in a table, and foreign keys are used to link records in different tables. Referential integrity is maintained through the use of foreign key constraints.
