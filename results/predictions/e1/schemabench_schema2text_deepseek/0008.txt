The database schema named "schemabench_0008" consists of 10 tables. The first table, "comfy_cms_sites", is used to store information about the various sites that can be managed using the Comfy CMS. Each site has an identifier, hostname, path, locale, and creation and update timestamps. The "id" field is the primary key and cannot be null.
The "comfy_cms_layouts" table stores information about the layouts of these sites. Each layout has a site id, parent id, app layout, label, identifier, content, css, js, position, and creation and update timestamps. The "id" field is the primary key and cannot be null. The "site_id" and "parent_id" fields are foreign keys referencing the "id" field in the "comfy_cms_sites" and "comfy_cms_layouts" tables respectively.
The "comfy_cms_pages" table stores information about the pages of these sites. Each page has a site id, layout id, parent id, target page id, label, slug, full path, content cache, position, children count, is published flag, and creation and update timestamps. The "id" field is the primary key and cannot be null. The "layout_id" and "parent_id" fields are foreign keys referencing the "id" field in the "comfy_cms_layouts" and "comfy_cms_pages" tables respectively. The "site_id" field is a foreign key referencing the "id" field in the "comfy_cms_sites" table.
The "comfy_cms_translations" table stores translations for pages and layouts. Each translation has a locale, page id, layout id, label, content cache, is published flag, and creation and update timestamps. The "id" field is the primary key and cannot be null. The "page_id" and "layout_id" fields are foreign keys referencing the "id" field in the "comfy_cms_pages" and "comfy_cms_layouts" tables respectively.
The "comfy_cms_fragments" table stores information about content fragments. Each fragment has a recordable id, recordable type, identifier, tag, content, boolean, datetime, and creation and update timestamps. The "id" field is the primary key and cannot be null.
The "comfy_cms_snippets" table stores information about snippets. Each snippet has a site id, label, identifier, content, position, and creation and update timestamps. The "id" field is the primary key and cannot be null. The "site_id" field is a foreign key referencing the "id" field in the "comfy_cms_sites" table.
The "comfy_cms_files" table stores information about files. Each file has a site id, label, description, position, and creation and update timestamps. The "id" field is the primary key and cannot be null. The "site_id" field is a foreign key referencing the "id" field in the "comfy_cms_sites" table.
The "comfy_cms_revisions" table stores revisions for snippets, pages, and layouts. Each revision has a record type, record id, data, and creation timestamp. The "id" field is the primary key and cannot be null. The "record_id" field is a foreign key referencing the "id" field in the "comfy_cms_snippets", "comfy_cms_pages", and "comfy_cms_layouts" tables.
The "comfy_cms_categories" table stores information about categories. Each category has a site id, label, and categorized type. The "id" field is the primary key and cannot be null. The "site_id" field is a foreign key referencing the "id" field in the "comfy_cms_sites" table.
The "comfy_cms_categorizations" table stores categorizations for snippets, pages, files, and categories. Each categorization has a category id, categorized type, and categorized id. The "id" field is the primary key and cannot be null. The "category_id" field is a foreign key referencing the "id" field in the "comfy_cms_categories" table. The "categorized_id" field is a foreign key referencing the "id" field in the "comfy_cms_snippets", "comfy_cms_pages", and "comfy_cms_files" tables.
