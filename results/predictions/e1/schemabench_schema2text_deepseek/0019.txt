The database schema named 'schemabench_0019' contains 12 tables. The primary purpose of this schema is to manage various aspects of an API monitoring and management system.
The 'accounts_profile' table represents user profiles, storing information such as the next report date, reports allowed, user ID, ping log limit, token, check limit, last SMS date, SMS limit, SMS sent, team limit, sort, nag period, next nag date, deletion notice date, and last active date. The 'accounts_project' table stores project-related information, including code, name, API key, API key read-only, owner ID, and badge key. The 'accounts_member' table maintains the membership of users in projects.
The 'api_channel' table stores information about API channels, including code, creation date, kind, value, email verification status, name, project ID, and last error. The 'api_channel_checks' table links API channels to checks, and the 'api_check' table stores information about API checks, including code, last ping, alert after, status, timeout, name, creation date, grace period, tags, number of pings, kind, schedule, timezone, confirmation link status, last ping failure status, description, last start, subject, project ID, last duration, and methods.
The 'api_flip' table records status changes of checks, including creation date, processing date, old status, new status, and owner ID. The 'api_notification' table stores notifications related to checks, including check status, creation date, channel ID, owner ID, error code, and channel ID.
The 'api_ping' table records pings, including creation date, remote address, method, user agent, owner ID, scheme, number of pings, body, and kind. The 'api_tokenbucket' table stores token bucket information, including value, tokens, and last updated date.
The 'auth_user' table stores user information, including password, last login, superuser status, username, first name, last name, email, staff status, active status, and date joined. Finally, the 'payments_subscription' table stores subscription information, including customer ID, payment method token, subscription ID, user ID, plan ID, address ID, invoice sending status, plan name, and invoice email.
All tables have foreign keys that reference other tables, ensuring data integrity and referential integrity.
