The database schema named 'schemabench_0074' consists of four tables: 'clicks', 'links', 'migrations', and 'users'.
The 'clicks' table is used to track user clicks on shortened URLs. It contains columns for the click's unique id, the user's IP address, the user's country, the referer URL, the referer host, the user's user agent, the id of the linked URL, and timestamps for when the click was created and last updated. The 'link_id' column is a foreign key referencing the 'id' in the 'links' table.
The 'links' table is used to store information about the shortened URLs. It contains columns for the link's unique id, the short URL, the original URL, the IP address of the creator, the id of the creator, the number of clicks on the link, a secret key for the link, whether the link is disabled, whether the link is custom, whether the link is for an API, and timestamps for when the link was created and last updated. The 'creator' column is a foreign key referencing the 'id' in the 'users' table.
The 'migrations' table is used to track database migrations. It contains a 'migration' column for the name of the migration and a 'batch' column for the batch number the migration belongs to.
The 'users' table is used to store information about the users. It contains columns for the user's unique id, the username, password, email, IP address, recovery key, role, whether the user is active, the user's API key, whether the API is active, the API quota, and timestamps for when the user was created and last updated. The 'deleted_at' column is nullable and is used to track when a user is deleted.
All columns allow null values except for the 'NOT NULL' constraints. Default values are not specified for any columns. Primary keys are denoted by asterisks next to the column names. Foreign keys are denoted by a 'FOREIGN KEY' constraint. Referential integrity is maintained by the foreign key constraints.
