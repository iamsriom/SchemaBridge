The database schema named schemabench_0076 consists of two tables: `checks` and `hosts`.
The `checks` table is used to store information about various checks that are run on hosts. It contains columns for the check's id, the id of the host it is associated with, the type of check, its status, whether it is enabled or not, the last run message, the last run output, the time the last run occurred, the next run time in minutes, the time when throttling started due to failing notifications, custom properties, and the creation and update timestamps. The `host_id` column is a foreign key referencing the `id` column in the `hosts` table.
The `hosts` table is used to store information about the hosts that are being checked. It contains columns for the host's id, the host's name, the ssh user, the port, the ip address, custom properties, and the creation and update timestamps.
Both tables have been created with NOT NULL constraints to ensure that all columns are always populated, except for the `enabled` column in the `checks` table and the `ssh_user`, `port`, `ip`, and `custom_properties` columns in the `hosts` table, which can be NULL. The `last_run_message`, `last_run_output`, `last_ran_at`, `next_run_in_minutes`, `started_throttling_failing_notifications_at`, `custom_properties`, `created_at`, and `updated_at` columns in the `checks` table and the `custom_properties` column in the `hosts` table are of type TEXT, JSON, TIME, and TIMESTAMP respectively.
The `checks` table has a primary key constraint on the `id` column and a foreign key constraint on the `host_id` column referencing the `id` column in the `hosts` table. The `hosts` table has a primary key constraint on the `id` column.
This schema ensures the integrity of the data by enforcing referential integrity through foreign key constraints, ensuring that all `host_id` values in the `checks` table correspond to a valid `id` in the `hosts` table.
