The database schema named "schemabench_0107" contains 8 tables. The tables are described as follows:
1. `account`: This table contains information about bank accounts. The primary key is `account_id`, which is an integer. The `district_id` is an integer and represents the district where the account is located. The `frequency` and `date` fields are strings and represent the frequency of transactions and the date of the last transaction, respectively. The `district_id` field is a foreign key referencing the `district` table.
2. `card`: This table contains information about bank cards. The primary key is `card_id`, which is an integer. The `disp_id` is an integer and represents the disposition id. The `type` and `issued` fields are strings and represent the type of the card and the date it was issued, respectively. The `disp_id` field is a foreign key referencing the `disp` table.
3. `client`: This table contains information about bank clients. The primary key is `client_id`, which is an integer. The `gender`, `birth_date`, and `district_id` fields are strings and represent the gender of the client, the birth date of the client, and the district where the client is located, respectively. The `district_id` field is a foreign key referencing the `district` table.
4. `disp`: This table contains information about bank dispositions. The primary key is `disp_id`, which is an integer. The `client_id` and `account_id` fields are integers and represent the client id and account id, respectively. The `type` field is a string and represents the type of disposition. The `account_id` and `client_id` fields are foreign keys referencing the `account` and `client` tables, respectively.
5. `district`: This table contains information about districts. The primary key is `district_id`, which is an integer. The fields `A2` to `A16` are strings and represent various attributes of the district.
6. `loan`: This table contains information about bank loans. The primary key is `loan_id`, which is an integer. The `account_id`, `date`, `amount`, `duration`, `payments`, and `status` fields are strings and represent the account id, the date of the loan, the amount of the loan, the duration of the loan, the payments made, and the status of the loan, respectively. The `account_id` field is a foreign key referencing the `account` table.
7. `order`: This table contains information about bank orders. The primary key is `order_id`, which is an integer. The `account_id`, `bank_to`, `account_to`, `amount`, `k_symbol` fields are strings and represent the account id, the bank to which the order is made, the account to which the order is made, the amount of the order, and the symbol of the order, respectively. The `account_id` field is a foreign key referencing the `account` table.
8. `trans`: This table contains information about bank transactions. The primary key is `trans_id`, which is an integer. The `account_id`, `date`, `type`, `operation`, `amount`, `balance`, `k_symbol`, `bank`, `account` fields are strings and represent the account id, the date of the transaction, the type of the transaction, the operation of the transaction, the amount of the transaction, the balance of the account after the transaction, the symbol of the transaction, the bank of the transaction, and the account of the transaction, respectively. The `account_id` field is a foreign key referencing the `account` table.
All tables allow null values except for the ones that have not specified not to allow null. The foreign keys have on delete no action and on update no action rules, meaning that if a record in the parent table is deleted or updated, no action will be taken on the corresponding records in the child table.
