The database schema named "schemabench_0151" consists of 14 tables. The primary purpose of this schema is to manage various aspects of an asset management system.
The "announcements" table is used to store announcements made by users. It has columns for the announcement id, the user id, the body of the announcement, the action text and url, and timestamps for creation and update. The user id is a foreign key referencing the id in the "users" table.
The "assets_departments" table is a junction table that links assets and departments. It has two columns for asset id and department id, both of which are primary keys. The asset id and department id are foreign keys referencing the id in the "assets" and "departments" tables respectively.
The "password_resets" table is used to store password reset requests. It has columns for the email, token, and timestamps for creation.
The "categories" table is used to store categories of assets. It has columns for the category id, name, parent category id, and timestamps for creation and update. The parent category id is a foreign key referencing the id in the "categories" table.
The "invoices" table is used to store invoices. It has columns for the invoice id, user id, amount, due date, status, and timestamps for creation and update. The user id is a foreign key referencing the id in the "users" table.
The "assets" table is used to store assets. It has columns for the asset id, name, serial number, manufacturer id, category id, location id, department id, user id, and timestamps for creation and update. The department id, manufacturer id, user id, and category id are foreign keys referencing the id in the "departments", "manufacturers", "users", and "categories" tables respectively.
The "api_tokens" table is used to store API tokens. It has columns for the token id, user id, name, token, expiry date, and timestamps for creation and update. The user id is a foreign key referencing the id in the "users" table.
The "notifications" table is used to store notifications. It has columns for the notification id, user id, message, read status, and timestamps for creation and update. The user id is a foreign key referencing the id in the "users" table.
The "tickets" table is used to store support tickets. It has columns for the ticket id, asset id, user id, status, description, and timestamps for creation and update. The asset id and user id are foreign keys referencing the id in the "assets" and "users" tables respectively.
The "maintenance" table is used to store maintenance records. It has columns for the maintenance id, asset id, description, date, and timestamps for creation and update. The asset id is a foreign key referencing the id in the "assets" table.
The "departments" table is used to store departments. It has columns for the department id, name, location id, and timestamps for creation and update. The location id is a foreign key referencing the id in the "locations" table.
The "locations" table is used to store locations. It has columns for the location id, name, address, and timestamps for creation and update.
The "manufacturers" table is used to store manufacturers. It has columns for the manufacturer id, name, and timestamps for creation and update.
Finally, the "users" table is used to store users. It has columns for the user id, email, name, password, remember token, and timestamps for creation and update. The email is unique to prevent duplicate users.
