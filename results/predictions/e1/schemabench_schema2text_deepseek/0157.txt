The database schema named 'schemabench_0157' consists of 17 tables. The database is designed to manage a library system, with tables representing various entities such as books, authors, publishers, categories, and customers.
The 'country' table holds information about different countries, with each country identified by a unique 'id_country' (a tinyint unsigned, auto-incrementing, and primary key).
The 'category' table contains different categories of books, each identified by a unique 'id_category' (a tinyint unsigned, auto-incrementing, and primary key).
The 'publisher' table contains information about different publishers, each identified by a unique 'id_publisher' (a smallint unsigned, auto-incrementing, and primary key).
The 'book_language' table represents different languages in which books can be published, each identified by a unique 'id_book_language' (a smallint unsigned, auto-incrementing, and primary key).
The 'book_status' table holds different statuses of books, each identified by a unique 'id_book_status' (a tinyint unsigned, auto-incrementing, and primary key).
The 'customer' table contains information about library customers, with each customer identified by a unique 'id_customer' (a smallint unsigned, auto-incrementing, and primary key). The 'first_name', 'last_name', 'dni', 'phone', 'email', and 'birth_date' columns are mandatory.
The 'book' table represents books in the library, each identified by a unique 'id_book' (a smallint unsigned, auto-incrementing, and primary key). The 'id_publisher', 'title', 'book_description', 'publication_date', and 'id_book_language' columns are mandatory. It references the 'publisher' and 'book_language' tables via foreign keys.
The 'book_inventory' table represents the inventory of books in the library, each identified by a unique 'id_book_inventory' (a smallint unsigned, auto-incrementing, and primary key). It references the 'book' and 'book_status' tables via foreign keys.
The 'storage_location' table represents the storage locations of books in the library, with each location identified by a unique 'id_book_inventory' (a smallint unsigned, and a composite primary key). It references the 'book_inventory' table via a foreign key.
The 'loan' table represents loans of books by customers, with each loan identified by a unique 'id_loan' (an int unsigned, auto-incrementing, and primary key). It references the 'customer' and 'book_inventory' tables via foreign keys.
The 'author' table represents authors of books, with each author identified by a unique 'id_author' (a smallint unsigned, auto-incrementing, and primary key). It references the 'country' table via a foreign key.
The 'book_author' table represents the association between books and authors, with each record identifying a book and an author. It references the 'author' and 'book' tables via foreign keys.
The 'book_category' table represents the association between books and categories, with each record identifying a book and a category. It references the 'category' and 'book' tables via foreign keys.
The 'book_return' table represents returns of books by customers, with each return identified by a unique 'id_book_return' (an int unsigned, auto-incrementing, and primary key). It references the 'loan' table via a foreign key.
Two logging tables 'log_statement' and 'log_loan' are also present, which log user queries and loan actions respectively. They reference the 'log_statement' table via foreign keys.
Finally, two logging tables 'log_deleted_book_return' and 'log_loan' are also present, which log deleted book returns and loan actions respectively.
This schema ensures data integrity by enforcing primary and foreign key constraints, and by maintaining referential integrity. It also includes indexes for efficient querying.
