The database schema named "schemabench_0167" consists of three tables: "reservations", "customers", and "room".
The "reservations" table is used to store information about customer reservations. It has five columns: "reservation_id", "customer_id", "check_in_date", "check_out_date", and "reservation_date". The "reservation_id" column is the primary key and auto-increments, while the "customer_id" and "room_number" columns are foreign keys referencing the "customer_id" and "room_number" columns in the "customers" and "room" tables, respectively.
The "customers" table is used to store information about customers. It has four columns: "customer_id", "first_name", "last_name", "email", and "phone". The "customer_id" column is the primary key and auto-increments.
The "room" table is used to store information about the rooms. It has five columns: "room_number", "beds", "max_occupants", "smoking_room", "pet_room", and "nightly_cost". The "room_number" column is the primary key and auto-increments. The "smoking_room" and "pet_room" columns are binary values indicating whether the room allows smoking and pet stays, respectively.
All columns allow null values except for "reservation_date" in the "reservations" table and "first_name", "last_name", "email", and "phone" in the "customers" table. The "reservation_date" column in the "reservations" table has a default value of the current date and time.
There are no unique or composite constraints in this schema. The primary keys and foreign keys enforce entity integrity. The foreign key constraints in the "reservations" table have the "CASCADE" update and delete rules, meaning that if the referenced record in the "customers" or "room" tables is updated or deleted, the corresponding records in the "reservations" table will also be updated or deleted.
There are no other indexes or constraints in this schema.
