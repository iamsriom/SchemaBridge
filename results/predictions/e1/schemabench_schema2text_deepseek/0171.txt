The database schema named "schemabench_0171" consists of six tables: `audit`, `counterparties`, `instrument`, `trader`, `trades`, and `tradestatus`.
The `audit` table is used to track the activities related to trades. It has columns for `AuditID` (an integer, primary key, auto-incremented), `TradeID` (an integer, foreign key referencing the `trades` table), `Activity` (a string of up to 100 characters), and `ActivityTimestamp` (a timestamp, defaulted to the current time and updated whenever the record is modified).
The `counterparties` table holds information about the counterparties involved in trades. It has columns for `TradeID` (an integer, primary key), `CounterpartyID` (an integer, primary key), `CounterpartyName` (a string of up to 100 characters), and `ExposureLimit` (a decimal number).
The `instrument` table contains information about the instruments involved in trades. It has columns for `InstrumentID` (an integer, primary key), `InstrumentLabel` (a string of up to 100 characters), `TradeID` (an integer, foreign key referencing the `trades` table), `MaturityDate` (a date), `SettlementType` (a string of up to 50 characters), and `Currency` (a string of up to 3 characters).
The `trader` table holds information about the traders involved in trades. It has columns for `TraderID` (an integer, primary key), `TraderName` (a string of up to 50 characters), `TraderEmail` (a string of up to 100 characters), and `TradeID` (an integer, foreign key referencing the `trades` table).
The `trades` table is the main table that holds information about trades. It has columns for `TradeID` (an integer, primary key), `Portfolio` (a string of up to 50 characters), `TradeDate` (a date), `InstrumentID` (an integer, foreign key referencing the `instrument` table), `Quantity` (an integer), `Price` (a decimal number), `Typology` (a string of up to 20 characters), `CounterpartyID` (an integer), `TraderID` (an integer, foreign key referencing the `trader` table), `Notional` (a decimal number), `FixedRate` (a decimal number), `FloatRateIndex` (a string of up to 50 characters), and `Spread` (a decimal number).
Finally, the `tradestatus` table tracks the status of trades. It has columns for `TradeID` (an integer, foreign key referencing the `trades` table), `StatusID` (an integer, primary key), and `StatusName` (a string of up to 50 characters).
All tables allow null values except for the ones that have a NOT NULL constraint. They also have foreign key relationships to ensure referential integrity and maintain the relationships between tables.
