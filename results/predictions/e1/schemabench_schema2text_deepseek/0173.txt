The database schema named "schemabench_0173" consists of 9 tables.
The "blood" table is used to store information about blood types and their compatibility with other types. It has two columns: "blood_type" which is a primary key and cannot be null, and "compatible_types" which stores a string of blood types that the given blood type is compatible with.
The "hospital" table stores information about hospitals. It has several columns including "hospital_id" as the primary key, "hospital_name", "address", "contact_number", "email", "head_doctor_name", "services_offered", and "emergency_services_availability" which indicates whether the hospital offers emergency services.
The "private_facility" table stores information about private medical facilities. It has similar columns to the "hospital" table, but without the "emergency_services_availability" column.
The "donor" table stores information about blood donors. It has columns for "donor_id" as the primary key, "first_name", "last_name", "date_of_birth", "gender", "contact_number", "email", and "home_address".
The "donor_medical" table stores medical information about donors. It has columns for "donor_medical_id" as the primary key, "donor_id" which references the "donor" table, "allergies", "weight", "blood_type", "medical_condition", and "medical_history" as well as "insurance_details".
The "patient" table stores information about patients. It has similar columns to the "donor" table.
The "patient_medical" table stores medical information about patients. It has columns for "patient_medical_id" as the primary key, "patient_id" which references the "patient" table, "blood_type", "allergies", "medical_condition", "medical_history", and "insurance_details".
The "blood_transfusion" table stores information about blood transfusions. It has columns for "transfusion_id" as the primary key, "patient_medical_id" which references the "patient_medical" table, "hospital_id" which references the "hospital" table, "private_facility_id" which references the "private_facility" table, "admission_date", "discharge_date", and "transfusion_date" as well as "room_number".
The "blood_donations" table stores information about blood donations. It has columns for "blood_donation_id" as the primary key, "donor_medical_id" which references the "donor_medical" table, "hospital_id" which references the "hospital" table, "private_facility_id" which references the "private_facility" table, "collection_date", "expiry_date", "contaminated", "blood_description", "component_type", "anticoagulant_used", and "quantity".
Each table has primary keys and foreign keys to enforce entity integrity and referential integrity. For instance, the "donor_medical" table has a foreign key "donor_id" which references the "donor" table, and the "blood_type" which references the "blood" table. This ensures that each donor medical record is associated with a valid donor and a valid blood type. Similarly, the "patient_medical" table has foreign keys "patient_id" and "blood_type" which reference the "patient" and "blood" tables respectively. The "blood_transfusion" and "blood_donations" tables have foreign keys referencing the "patient_medical", "hospital", and "private_facility" tables respectively.
