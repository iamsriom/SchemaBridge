The database schema named "schemabench_0174" consists of 15 tables. The primary purpose of this schema is to manage various aspects of healthcare.
The "physician" table represents a list of healthcare professionals. It includes columns for the employee ID, name, position, and social security number. The primary key is the employee ID.
The "department" table holds information about different departments within the healthcare system. It includes columns for the department ID, name, and the head of the department. The primary key is the department ID.
The "affiliated_with" table establishes the relationship between physicians and departments. It includes columns for the physician ID, department ID, and whether the physician is the primary affiliation. The foreign keys are the physician ID and department ID, both referencing the respective tables.
The "medical_procedure" table lists all the medical procedures available. It includes columns for the code, name, and cost of each procedure. The primary key is the code.
The "trained_in" table shows which physicians are trained in which procedures. It includes columns for the physician ID, treatment ID, certification date, and certification expiration date. The foreign keys are the physician ID and treatment ID, both referencing the respective tables.
The "patient" table contains information about patients. It includes columns for the social security number, name, address, phone number, insurance ID, and PCP ID. The primary key is the social security number. The PCP ID is a foreign key referencing the physician table.
The "nurse" table lists all nurses. It includes columns for the employee ID, name, position, and registration status. The primary key is the employee ID.
The "appointments" table holds information about appointments. It includes columns for the appointment ID, patient ID, prep nurse ID, physician ID, start date and time, end date and time, and examination room. The foreign keys are the patient ID, prep nurse ID, and physician ID, all referencing the respective tables.
The "medication" table lists all medications. It includes columns for the code, name, brand, and description. The primary key is the code.
The "prescribes" table shows which physicians prescribe which medications to which patients on which dates. It includes columns for the physician ID, patient ID, medication ID, date, appointment ID, and dose. The foreign keys are all referencing the respective tables.
The "block" and "room" tables are related to the hospital's layout. The "block" table includes columns for the block floor ID and block code ID, and the primary key is a composite of both. The "room" table includes columns for the room number, room type, block floor ID, block code ID, and availability. The foreign key is the composite of block floor ID and block code ID, referencing the "block" table.
The "on_call" table shows which nurses are on call for which blocks. It includes columns for the nurse ID, block floor ID, block code ID, on-call start date, and on-call end date. The foreign keys are the nurse ID and the composite of block floor ID and block code ID, referencing the respective tables.
The "stay" table holds information about patient stays. It includes columns for the stay ID, patient ID, room ID, start time, and end time. The foreign keys are the patient ID and room ID, both referencing the respective tables.
Finally, the "undergoes" table shows which patients undergo which procedures at which times. It includes columns for the patient ID, procedure ID, stay ID, date, physician ID, and assisting nurse ID. The foreign keys are all referencing the respective tables.
This schema ensures data integrity by enforcing primary and foreign key constraints, and by maintaining referential integrity through the use of cascade and restrict options on foreign key constraints.
