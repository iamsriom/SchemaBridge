The database schema named 'schemabench_0176' consists of 9 tables. The database is designed to manage various aspects related to water supply, including the types of water, the water sources, deliveries, jobs, departments, workers, and records of water balance.
The 'UNIT_MEASURES' table holds information about different unit measures. Each record has an 'id_um' (a unique identifier) and a 'title_um' (a name for the unit measure).
The 'WATER_TYPES' table contains information about different types of water. Each record has an 'id_type' (a unique identifier), a 'title' (the name of the water type), and a 'description' (a brief description of the water type).
The 'WATERS' table stores information about the water sources. Each record has a 'registration_number' (a unique identifier), a 'mark' (a mark for the water source), a 'note' (a note about the water source), and an 'id_type' (the type of the water). The 'id_type' is a foreign key referencing the 'id_type' in the 'WATER_TYPES' table.
The 'SUPPLIERS' table contains information about the suppliers. Each record has a 'code_supplier' (a unique identifier), a 'name_supplier' (the name of the supplier), an 'address_supplier' (the address of the supplier), a 'phone_supplier' (the phone number of the supplier), and an 'email_supplier' (the email of the supplier).
The 'DELIVERIES' table records deliveries. Each record has a 'deliver_date' (the date of the delivery), a 'supplier_code' (the supplier code), a 'registration_number' (the water registration number), an 'ammount' (the amount of water delivered), a 'note' (a note about the delivery), and an 'id_um' (the unit measure). The 'supplier_code' and 'registration_number' are foreign keys referencing the 'code_supplier' and 'registration_number' in the 'SUPPLIERS' and 'WATERS' tables, respectively.
The 'JOBS' table holds information about jobs. Each record has a 'serial_number' (a unique identifier), a 'job_title' (the title of the job), and an 'expected_number_of_workers' (the expected number of workers for the job).
The 'DEPARTMENTS' table contains information about departments. Each record has a 'code' (a unique identifier), a 'title' (the name of the department), and an 'expected_number_of_workers' (the expected number of workers for the department).
The 'WORKERS' table records workers. Each record has a 'security_number' (a unique identifier), a 'name' (the name of the worker), a 'lastname' (the last name of the worker), a 'shift' (the shift of the worker), a 'birth' (the birth date of the worker), an 'address' (the address of the worker), a 'phone' (the phone number of the worker), a 'suspended' (whether the worker is suspended or not), an 'injury' (whether the worker has an injury or not), a 'departments_code' (the department code of the worker), and a 'serial_number_job' (the job serial number of the worker). The 'departments_code' and 'serial_number_job' are foreign keys referencing the 'code' and 'serial_number' in the 'DEPARTMENTS' and 'JOBS' tables, respectively.
The 'RECORDS_OF_WATER_BALANCE' table records records of water balance. Each record has a 'record_date' (the date of the record), a 'registration_number' (the water registration number), a 'security_number' (the worker security number), an 'initial_state' (the initial state of the water), an 'end_state' (the end state of the water), and a 'note' (a note about the record). The 'registration_number' and 'security_number' are foreign keys referencing the 'registration_number' and 'security_number' in the 'WATERS' and 'WORKERS' tables, respectively.
The 'WORKERS' table has a CHECK constraint ensuring that the 'shift' column only accepts values 1, 2, or 3.
This schema is designed to ensure data integrity by enforcing primary and foreign key constraints, and by using CHECK constraints to enforce domain integrity.
