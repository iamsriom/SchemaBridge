The database schema named "schemabench_0179" contains 12 tables.
The "drivers" table is used to store information about the drivers. It includes fields like id, title, first name, last name, nickname, name suffix, sex, date of birth, and country. The primary key is the id field, which is auto-incremented. The sex field is an ENUM type, which means it can only take the values 'M' or 'F'. The country field is a fixed-length character field and cannot be null.
The "circuits" table stores information about the racing circuits. It includes fields like id, name, since date, length in kilometers, length in miles (which is generated from the kilometer length), layout, and changes. The primary key is the id field, which is auto-incremented. The length in miles is generated as the kilometer length times 0.621371192.
The "races" table stores information about the races. It includes fields like id, circuit id, event date, start time, whether it's cancelled, cancellation reason, distance in kilometers, distance in miles (which is generated from the kilometer distance), laps, average speed in kilometers per hour, and average speed in miles per hour. The primary key is the id field. The circuit id is a foreign key referencing the id field in the circuits table. The distance in miles is generated as the kilometer distance times 0.621371192. The average speed in kilometers per hour is generated as the distance in kilometers divided by 24. The average speed in miles per hour is generated as the average speed in kilometers per hour times 0.621371192.
The "cars" table stores information about the cars. It includes fields like id, car class, car chassis, and car engine. The primary key is the id field, which is auto-incremented.
The "car_numbers" table stores information about the car numbers. It includes fields like id, race id, car id, and number. The primary key is the id field, which is auto-incremented. The race id and car id are foreign keys referencing the id fields in the races and cars tables, respectively.
The "results" table stores information about the results. It includes fields like id, race id, car id, position, laps, distance, racing time, and reason. The primary key is the id field, which is auto-incremented. The race id and car id are foreign keys referencing the id fields in the races and car_numbers tables, respectively.
The "results_in" table stores information about the results in. It includes fields like id, race year, position, car class, car number, team country, team name, drivers country, drivers name, car chassis, car engine, car tyres, laps, distance, racing time, reason, and processed. The primary key is the id field, which is auto-incremented.
The "teams" table stores information about the teams. It includes fields like id, title, country, and whether it's a private entrant. The primary key is the id field, which is auto-incremented.
The "tyres" table stores information about the tyres. It includes fields like id and brand. The primary key is the id field.
The "car_tyres" table stores information about the tyres used by the cars. It includes fields like car id and tyre id. The car id and tyre id are foreign keys referencing the id fields in the car_numbers and tyres tables, respectively.
The "driver_results" table stores information about the results of the drivers. It includes fields like driver id, result id, and order number. The driver id and result id are foreign keys referencing the id fields in the drivers and results tables, respectively.
The "team_results" table stores information about the results of the teams. It includes fields like team id, result id, and order number. The team id and result id are foreign keys referencing the id fields in the teams and results tables, respectively.
All fields allow null values except for the ones that are marked as not null. The update rule is cascade on update and restrict on delete for all foreign keys.
