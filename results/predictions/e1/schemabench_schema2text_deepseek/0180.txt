The database schema named 'schemabench_0180' consists of two tables: 'aircraft' and 'traffic'.
The 'aircraft' table is used to store information about aircraft, including details such as the aircraft's unique identifier (db_key), registration details, manufacturer details, model information, type code, serial number, line number, aircraft type, operator details, test registration status, built date, first flight date, seat configuration, engine details, modes, ADS-B capability, ACARS capability, and notes. Each column in the 'aircraft' table has a specific data type (e.g., VARCHAR for text fields, TIMESTAMP for date and time fields, and BOOLEAN for boolean fields). All columns allow null values except for the 'db_key' column which is a serial primary key.
The 'traffic' table is used to store information about traffic, including details such as the aircraft's callsign, number, registration details, type code, origin, destination, first and last seen times, day, latitude and longitude coordinates, and altitude details. Each column in the 'traffic' table has a specific data type (e.g., VARCHAR for text fields, TIMESTAMP for date and time fields, and DOUBLE PRECISION for latitude and longitude fields). All columns allow null values except for the 'db_key' column which is a serial primary key.
The 'aircraft' and 'traffic' tables are related through the 'db_key' column, which is a foreign key in the 'traffic' table referencing the primary key in the 'aircraft' table. This schema ensures referential integrity, ensuring that the 'traffic' data corresponds to valid 'aircraft' data.
The schema also includes various constraints and indexes to enforce data integrity and optimize query performance.
