The database schema named "schemabench_0190" consists of five tables: `user`, `topic`, `post`, `comment`, and `vote`.
The `user` table represents a user of the system. It has three columns: `id` (an integer primary key auto-incremented), `username` (a string of up to 25 characters), and `last_login` (a timestamp). The `username` column is unique and cannot be null.
The `topic` table represents a topic in the system. It has four columns: `id` (an integer primary key auto-incremented), `topicname` (a string of up to 30 characters), `topicdesc` (a string of up to 500 characters), and `topicdate` (a timestamp). The `topicname` column is unique and cannot be null.
The `post` table represents a post in the system. It has eight columns: `id` (an integer primary key auto-incremented), `posttitle` (a string of up to 100 characters), `url` (a string of up to 2000 characters), `text_content` (a string), `user_id` (an integer foreign key referencing the `user` table), `topic_id` (an integer foreign key referencing the `topic` table), `last_post` (a timestamp), and `post_id` (an integer foreign key referencing the `post` table). The `posttitle` column cannot be null.
The `comment` table represents a comment in the system. It has seven columns: `id` (an integer primary key auto-incremented), `text` (a string of up to 255 characters), `parent_comment_id` (an integer foreign key referencing the `comment` table), `user_id` (an integer foreign key referencing the `user` table), `post_id` (an integer foreign key referencing the `post` table), `date_commented` (a timestamp), and `comment_id` (an integer foreign key referencing the `comment` table). The `text` column cannot be null.
The `vote` table represents a vote in the system. It has four columns: `id` (an integer primary key auto-incremented), `user_id` (an integer foreign key referencing the `user` table), `post_id` (an integer foreign key referencing the `post` table), and `vote` (a small integer with a check constraint to ensure it is either 1 or -1).
All foreign keys in this schema follow the referential integrity rules. If a record in the parent table is deleted, the corresponding records in the child tables are set to null (for `ON DELETE SET NULL`), or are deleted (for `ON DELETE CASCADE`).
