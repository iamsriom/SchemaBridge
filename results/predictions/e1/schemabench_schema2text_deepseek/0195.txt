The database schema named 'schemabench_0195' consists of six tables. The main purpose of this schema is to manage various aspects of a pizza ordering and delivery service.
The 'runners' table represents the runner's information. It has two columns: 'runner_id', which is an integer and 'registration_date', which is a date. This table is used to keep track of the runners and their registration dates.
The 'customer_orders' table is used to store information about customer orders. It has five columns: 'order_id', 'customer_id', 'pizza_id', 'exclusions', 'extras', and 'order_time'. 'order_id' is an integer that uniquely identifies each order. 'customer_id' is an integer that represents the customer who placed the order. 'pizza_id' is an integer that identifies the type of pizza ordered. 'exclusions' and 'extras' are varchar fields that represent any ingredients that were excluded or added to the pizza. 'order_time' is a timestamp that records when the order was placed.
The 'runner_orders' table contains information about the orders assigned to runners. It has six columns: 'order_id', 'runner_id', 'pickup_time', 'distance', 'duration', and 'cancellation'. 'order_id' and 'runner_id' are integers that link the order to the runner. 'pickup_time' is a varchar field that records the time the runner picked up the order. 'distance' and 'duration' are varchar fields that record the distance and duration of the delivery. 'cancellation' is a varchar field that records any cancellation information.
The 'pizza_recipes' table contains information about the recipes of the pizzas. It has two columns: 'pizza_id' and 'toppings'. 'pizza_id' is an integer that identifies the pizza and 'toppings' is a varchar field that lists the toppings on the pizza.
The 'pizza_names' table contains information about the names of the pizzas. It has two columns: 'pizza_id' and 'pizza_name'. 'pizza_id' is an integer that identifies the pizza and 'pizza_name' is a varchar field that records the name of the pizza.
The 'pizza_toppings' table contains information about the toppings. It has two columns: 'topping_id' and 'topping_name'. 'topping_id' is an integer that uniquely identifies each topping and 'topping_name' is a varchar field that records the name of the topping.
All tables allow null values except for 'runner_id' in the 'runners' table, 'order_id' in the 'customer_orders' table, and 'pizza_id' in the 'runner_orders', 'pizza_recipes', 'pizza_names', and 'pizza_toppings' tables. The primary keys are 'runner_id' in the 'runners' table, 'order_id' in the 'customer_orders' and 'runner_orders' tables, and 'pizza_id' in the 'pizza_recipes', 'pizza_names', and 'pizza_toppings' tables. The composite or unique constraints are 'order_id' in the 'customer_orders' and 'runner_orders' tables, and 'pizza_id' in the 'pizza_recipes', 'pizza_names', and 'pizza_toppings' tables. The foreign keys are 'runner_id' in the 'runner_orders' table referencing 'runner_id' in the 'runners' table, 'pizza_id' in the 'customer_orders' and 'runner_orders' tables referencing 'pizza_id' in the 'pizza_recipes', 'pizza_names', and 'pizza_toppings' tables. The update and delete rules are set to CASCADE or RESTRICT.
