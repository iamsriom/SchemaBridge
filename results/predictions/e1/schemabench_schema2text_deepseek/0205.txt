The database schema named "schemabench_0205" consists of 6 tables. The tables are defined as follows:
1. The "genres" table, with GENRE_ID as the primary key, is used to store information about different movie genres. It includes GENRE_NAME and DESCRIPTION fields.
2. The "directors" table, with DIRECTOR_ID as the primary key, stores information about movie directors. It includes FIRST_NAME, LAST_NAME, BIRTH_DATE, NATIONALITY, WEBSITE, and BIOGRAPHY fields. The ACTOR_ID field is a foreign key referencing the actors table.
3. The "rates" table, with RATE_ID as the primary key, stores movie ratings. It includes MOVIE_ID, GENRE_ID, DIRECTOR_ID, and RATE fields. The MOVIE_ID, GENRE_ID, and DIRECTOR_ID fields are foreign keys referencing the movies, genres, and directors tables respectively.
4. The "movies" table, with MOVIE_ID as the primary key, stores information about movies. It includes MOVIE_TITLE, RELEASE_DATE, DURATION, GENRE_ID, DIRECTOR_ID, RATE_ID, and DESCRIPTION fields. The GENRE_ID and DIRECTOR_ID fields are foreign keys referencing the genres and directors tables respectively. The RATE_ID field is a foreign key referencing the rates table.
5. The "actors" table, with ACTOR_ID as the primary key, stores information about actors. It includes FIRST_NAME, LAST_NAME, BIRTH_DATE, NATIONALITY, WEBSITE, and BIOGRAPHY fields. The DIRECTOR_ID field is a foreign key referencing the directors table.
6. The "movie_actor" table, which links the movies and actors tables together. It includes MOVIE_ID and ACTOR_ID fields, both of which are foreign keys referencing the movies and actors tables respectively.
The schema ensures referential integrity by enforcing foreign key constraints. This means that any data that is stored in the "movies", "rates", and "movie_actor" tables must correspond to data that is already stored in the "genres", "directors", and "actors" tables respectively.
