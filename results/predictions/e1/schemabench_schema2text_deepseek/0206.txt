The database schema named 'schemabench_0206' contains 11 tables. The main purpose of this schema is to manage user accounts, posts, comments, likes, friendships, messages, notifications, groups, and administrative tasks.
The 'users' table is the main entity, storing information about each user, including their unique ID, username, password, name, email, phone number, address, registration date, admin status, and a description. The USER_ID is the primary key and auto-increments. The USER_NAME, PASSCODE, FIRST_NAME, MIDDLE_NAME, LAST_NAME, EMAIL, and PHONE_NUMBER fields are required and cannot be null. The MIDDLE_NAME field has a default value of "_".
The 'accounts' table stores information about user accounts, including the account ID, user ID, account type, and a description. The ACCOUNT_ID is the primary key and references the USER_ID in the 'users' table.
The 'comments' table stores information about comments made by users on posts. It includes the comment ID, post ID, user ID, comment text, and comment date. The COMMENT_ID is the primary key and references both the POST_ID and USER_ID in the 'posts' and 'users' tables respectively.
The 'posts' table stores information about user posts. It includes the post ID, user ID, content, post date, and post type. The POST_ID is the primary key and references the USER_ID in the 'users' table.
The 'likes' table stores information about likes on posts. It includes the like ID, post ID, user ID, and like date. The LIKE_ID is the primary key and references both the POST_ID and USER_ID in the 'posts' and 'users' tables respectively.
The 'friendship' table stores information about user friendships. It includes the friendship ID, user IDs, and friendship date. The FRIENDSHIP_ID is the primary key and references both the USER_ID1 and USER_ID2 in the 'users' table.
The 'messages' table stores information about user messages. It includes the message ID, sender ID, receiver ID, text, message date, and read status. The MESSAGE_ID is the primary key and references both the SENDER_ID and RECEIVER_ID in the 'users' table.
The 'notifications' table stores information about user notifications. It includes the notification ID, user ID, notification text, notification date, and read status. The NOTIFICATION_ID is the primary key and references the USER_ID in the 'users' table.
The 'groups_' table stores information about user groups. It includes the group ID, group name, creator ID, and creation date. The GROUP_ID is the primary key and references the CREATOR_ID in the 'users' table.
The 'admins' table stores information about group administrators. It includes the admin ID, user ID, and group ID. The ADMIN_ID is the primary key and references both the USER_ID and GROUP_ID in the 'users' and 'groups_' tables respectively.
The 'group_members' table stores information about group members. It includes the group member ID, group ID, user ID, and join date. The GROUP_MEMBER_ID is the primary key and references both the GROUP_ID and USER_ID in the 'groups_' and 'users' tables respectively.
All tables have foreign keys that reference primary keys in other tables, ensuring referential integrity and maintaining the relationships between tables.
