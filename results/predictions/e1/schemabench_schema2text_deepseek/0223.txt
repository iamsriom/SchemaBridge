The database schema named "schemabench_0223" consists of 7 tables.
The "Candidate" table is used to store information about the candidates participating in the election. It includes columns for CandidateId, Name, ServiceId, Designation, WorkPlace, MobileNo, Email, and PhotoPath. The CandidateId is the primary key and auto-increments.
The "CandidatePosition" table is used to map the candidates to the positions they are running for. It includes columns for CandidatePositionId, CandidateId, and PositionId. Both CandidatePositionId and CandidateId are primary keys and auto-increment.
The "Position" table is used to store information about the positions in the election. It includes columns for PositionId and PositionName, and NumberOfPost. PositionId is the primary key and auto-increments.
The "Role" table is used to store information about the roles of the users. It includes columns for RoleId and RoleType. RoleId is the primary key and auto-increments.
The "User" table is used to store information about the users. It includes columns for UserId, Name, ServiceId, MobileNo, Email, Password, and RoleId. UserId is the primary key.
The "VoteCastingInformation" table is used to store information about the votes cast by the voters. It includes columns for Id, CandidateId, VoterId, and PositionId. Id is the primary key and auto-increments.
The "Voter" table is used to store information about the voters. It includes columns for VoterId, Name, ServiceId, MobileNo, Email, BloodGroup, IsSelected, IsCommittedVote, UniqueIdentification, and IsMailSent. VoterId is the primary key and auto-increments. The IsSelected and IsCommittedVote columns have a default value of 0 and are not null. The UniqueIdentification column has a default value of a new UUID.
This schema is designed to ensure referential integrity by having foreign keys in the "CandidatePosition" and "VoteCastingInformation" tables that reference the primary keys in the "Candidate" and "Position" tables respectively. It also ensures entity integrity by having primary keys and unique constraints on the columns. The schema also includes indexes on the columns that are frequently queried.
