This database schema is named "schemabench_0227" and it consists of 21 tables. The primary purpose of this schema is to manage various aspects of flight operations.
The "Airline" table represents airlines, storing information about their names, HQ locations, and logos. Each airline is uniquely identified by a name.
The "AirportAbbreviation" table holds information about airport abbreviations. Each abbreviation is a unique key.
The "Airport" table contains information about airports, including their names, locations, and radio operators. It references the "AirportAbbreviation" table via the airport abbreviation.
The "AirportAirline" table acts as a junction table that connects airports and airlines. It references both the "Airport" and "Airline" tables.
The "Amenity" table holds information about various amenities, including their codes and names. The amenity code is the primary key.
The "FlightCrew" table holds information about flight crews, including their IDs and sizes. The crew ID is the primary key.
The "FlightSchedule" table holds information about flight schedules, including the departure and arrival times, origin and destination airports, and the associated crew. It references the "Airline", "FlightCrew", "Airport" tables via their respective keys.
The "Model" table holds information about airplane models, including their names, manufacturers, and the number of passengers they can carry. The combination of model name and manufacturer is the primary key.
The "Airplane" table holds information about airplanes, including their tail numbers, airline, model, manufacturer, and nicknames. It references the "Airline" and "Model" tables via their respective keys.
The "Role" table holds information about roles in the flight crew. Each role is uniquely identified by a name.
The "CrewMember" table holds information about crew members, including their FAA numbers, names, sex, and role. It references the "Role" table via the role name.
The "FlightCrew_CrewMember" table acts as a junction table that connects flight crews and crew members. It references both the "FlightCrew" and "CrewMember" tables.
The "Status" table holds information about flight statuses. Each status is uniquely identified by a name.
The "FlightInstance" table holds information about individual flights, including their IDs, flight numbers, airplane, status, departure and arrival times, number of registered passengers, and origin and destination airports. It references the "FlightSchedule", "Airplane", and "Status" tables via their respective keys.
The "ChargableInstance" table acts as a junction table that connects flight instances and amenities. It references the "FlightInstance" table via the flight instance ID.
The "AmenityChargableInstance" table holds information about amenities and flight instances, linking them together. It references both the "Amenity" and "ChargableInstance" tables via their respective keys.
The "DomesticInstance" table acts as a junction table that connects flight instances and domestic flights. It references the "ChargableInstance" table via the flight instance ID.
The "IncidentReport" table holds information about incident reports, including the incident ID, flight instance, reporter and reported FAA numbers, incident type, report time, and description. It references the "FlightInstance" table via the flight instance ID.
The "InternationalInstance" table acts as a junction table that connects flight instances and international flights. It references the "ChargableInstance" table via the flight instance ID.
The "LocalInstance" table acts as a junction table that connects flight instances and local flights. It references the "ChargableInstance" table via the flight instance ID.
The "PersonnelReport" table holds information about personnel reports, including the incident ID, sentiment, reported FAA number, and the incident ID and sentiment are the primary key. It references the "IncidentReport" table via the incident ID.
This schema ensures referential integrity by enforcing foreign key constraints, ensuring that all data in the tables is valid and consistent. It also allows for easy querying and updating of data, as all tables are related in a logical and intuitive way.
