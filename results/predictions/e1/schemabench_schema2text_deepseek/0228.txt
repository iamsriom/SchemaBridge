The database schema named "schemabench_0228" consists of seven tables.
The "user" table is used to store user information. It includes columns for UserId, FirstName, LastName, PhoneNumber, and Address. The UserId is the primary key.
The "userauthentication" table stores user authentication information. It includes columns for UserId and EmailAddress, with UserId as the primary key and a foreign key referencing the UserId in the user table.
The "vendor" table stores vendor information. It includes columns for VendorId, PhoneNumber, Address, FirstName, LastName, VendorName, and Type. VendorId is the primary key.
The "menuitem" table stores information about the menu items offered by the vendors. It includes columns for VendorId, ItemName, and Price. The combination of VendorId and ItemName form the primary key and VendorId is a foreign key referencing the VendorId in the vendor table.
The "coupon" table stores coupon information. It includes columns for CouponId, DiscountPercentage, Active, UserId, and VendorId. CouponId is the primary key and UserId and VendorId are foreign keys referencing the UserId and VendorId in the user and vendor tables respectively.
The "FinalTable" table is a summary table that stores average price and customer status. It includes columns for AvgPrice and CustStatus.
The "orders" table stores information about user orders. It includes columns for OrderId, VendorId, UserId, Item, OrderDate, Ratings, Total, and TransactionId. TransactionId is the primary key and UserId and VendorId are foreign keys referencing the UserId and VendorId in the user and vendor tables respectively.
All tables allow null values except for the primary key columns. Default values are set for UserId and VendorId in the coupon table.
There are no other indexes or constraints in this schema. The schema is designed with entity integrity in mind, with each table's primary key acting as a unique identifier for each record. Referential integrity is also maintained through foreign key constraints, ensuring that all foreign keys in child tables reference valid primary keys in parent tables.
