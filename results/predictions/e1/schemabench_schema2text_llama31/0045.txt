The schemabench_0045 database is designed to store information about various entities related to GitHub repositories, user accounts, and subscription plans. The database consists of 11 tables: app_installations, app_installation_permissions, comments, labels, notifications, pinned_searches, repositories, subjects, subscription_plans, subscription_purchases, and users. The app_installations table stores information about GitHub applications, including their IDs, GitHub IDs, and permissions. The app_installation_permissions table links these applications to user accounts, tracking the permissions granted to each user. The comments table stores comments made on various subjects, including the subject ID, author, and body of the comment. The labels table stores labels assigned to subjects, with each label having a name, color, and subject ID. The notifications table stores notifications sent to users, including the subject title, URL, and reason for the notification. The pinned_searches table stores search queries pinned by users, along with the user ID and query name. The repositories table stores information about GitHub repositories, including their full names, private status, and owner. The subjects table stores information about various subjects, including their URLs, states, and authors. The subscription_plans table stores information about subscription plans, including their names, descriptions, and prices. The subscription_purchases table stores information about subscription purchases, including the subscription plan ID, account ID, and billing cycle. The users table stores information about user accounts, including their GitHub IDs, login names, and refresh intervals. Each table has various columns with specific data types, such as BIGINT, INT, VARCHAR, and DATETIME, and some columns allow null values while others do not. Primary keys are established for each table to uniquely identify each record, and foreign keys are used to link related tables together, such as the user ID in the app_installation_permissions table referencing the ID in the users table. Update and delete rules are also specified for some foreign keys, such as CASCADE for the user ID in the notifications table referencing the ID in the users table. Additionally, some tables have unique constraints and indexes to ensure data consistency and improve query performance.
