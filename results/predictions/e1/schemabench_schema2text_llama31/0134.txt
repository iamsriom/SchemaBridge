The schemabench_0134 database is a comprehensive system for managing financial data, particularly for companies and their interactions with customers and the stock market. It consists of 33 tables, each representing a distinct entity or relationship within this domain. The E_ACCOUNT_PERMISSION table stores information about account permissions, linking customer accounts to specific permissions and tax IDs. The E_ADDRESS table holds address details, with each address associated with a unique zip code from the E_ZIP_CODE table. The E_BROKER table contains information about brokers, including their status, number of trades, and commission total. The E_CASH_TRANSACTION table tracks cash transactions, referencing the E_TRADE table for trade details. The E_CHARGE table stores charge information, linked to trade types in the E_TRADE_TYPE table. The E_COMMISSION_RATE table contains commission rates for different trade types, exchanges, and quantity ranges. The E_COMPANY table stores company data, including their status, name, industry, and address, with foreign keys referencing the E_ADDRESS, E_INDUSTRY, and E_STATUS_TYPE tables. The E_COMPANY_COMPETITOR table lists competitors for each company, referencing the E_COMPANY and E_INDUSTRY tables. The E_CUSTOMER table stores customer information, including their tax ID, status, and address, with a foreign key referencing the E_ADDRESS table. The E_CUSTOMER_ACCOUNT table links customers to their accounts, referencing the E_BROKER and E_CUSTOMER tables. The E_CUSTOMER_TAXRATE table stores tax rates for each customer, referencing the E_CUSTOMER and E_TAXRATE tables. The E_DAILY_MARKET table tracks daily market data for each security, referencing the E_SECURITY table. The E_EXCHANGE table stores exchange information, including their name, number of symbols, and address, with a foreign key referencing the E_ADDRESS table. The E_FINANCIAL table contains financial data for each company, including revenue, net earnings, and basic and diluted earnings per share. The E_HOLDING table stores holding information, referencing the E_HOLDING_SUMMARY and E_TRADE tables. The E_HOLDING_HISTORY table tracks changes in holdings over time, referencing the E_HOLDING and E_TRADE tables. The E_HOLDING_SUMMARY table provides a summary of holdings for each customer account, referencing the E_CUSTOMER_ACCOUNT and E_SECURITY tables. The E_INDUSTRY table stores industry information, including the sector ID, with a foreign key referencing the E_SECTOR table. The E_LAST_TRADE table tracks the last trade for each security, referencing the E_SECURITY table. The E_NEWS_ITEM table stores news items, including headlines, summaries, and items, with a foreign key referencing the E_COMPANY table. The E_NEWS_XREF table links news items to companies, referencing the E_NEWS_ITEM and E_COMPANY tables. The E_SECTOR table stores sector information, including the sector name. The E_SECURITY table stores security information, including the symbol, issue, status, exchange, and company ID, with foreign keys referencing the E_COMPANY, E_EXCHANGE, and E_STATUS_TYPE tables. The E_SETTLEMENT table tracks settlements, referencing the E_TRADE table. The E_STATUS_TYPE table stores status type information, including the status name. The E_TAXRATE table stores tax rate information, including the tax name and rate. The E_TRADE table stores trade information, including the trade date, status, trade type, security symbol, and customer account ID, with foreign keys referencing the E_CUSTOMER_ACCOUNT, E_STATUS_TYPE, E_SECURITY, and E_TRADE_TYPE tables. The E_TRADE_HISTORY table tracks the status history of each trade, referencing the E_TRADE and E_STATUS_TYPE tables. The E_TRADE_REQUEST table stores trade requests, referencing the E_TRADE, E_TRADE_TYPE, E_SECURITY, and E_CUSTOMER_ACCOUNT tables. The E_TRADE_TYPE table stores trade type information, including the trade name, sell flag, and market flag. The E_WATCH_ITEM table stores watch list items, referencing the E_SECURITY and E_WATCH_LIST tables. The E_WATCH_LIST table stores watch lists, referencing the customer ID in the E_CUSTOMER table.
