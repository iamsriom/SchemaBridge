It contains nine tables: abilities, users, model_has_abilities, roles, tenants, assigned_roles, permissions, activity_logs, and model_has_roles. The abilities table stores information about the abilities or permissions within the system, including a unique identifier, name, title, entity ID, entity type, and scope, with the ability to store additional options in a JSON format. The users table holds information about the users, including their ID, name, email, password, and timestamps for when they were created and last updated. The model_has_abilities table links abilities to specific models, with each link having a unique combination of model type, model ID, and ability ID. The roles table contains information about the roles within the system, including a unique identifier, name, title, level, and scope, with timestamps for when they were created and last updated. The tenants table stores information about the tenants, including their ID, name, and timestamps for when they were created and last updated. The assigned_roles table links roles to entities, with each link having a unique combination of role ID, entity ID, and entity type, and optionally a restricted ID and type. The permissions table links abilities to entities, with each link having a unique ability ID, entity ID, and entity type, and a forbidden flag. The activity_logs table stores information about the activities performed within the system, including the type of loggable object, its ID, the action taken, the user who performed the action, and the timestamp when the action was performed. The model_has_roles table links roles to models, with each link having a unique combination of role ID, model type, and model ID. The abilities table has a primary key on its ID column, and the users, model_has_abilities, roles, tenants, assigned_roles, permissions, activity_logs, and model_has_roles tables also have primary keys on their ID columns.
